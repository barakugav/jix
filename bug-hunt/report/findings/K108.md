# K108: var/std of finite data whose deviations overflow returns NaN for 3+ elements (var([1e308, -1e308, 0.0]) = NaN, numpy inf)

- Severity: low  Verdict: confirmed  Category: wrong-result
- Location: jix/src/ops/reduction/variance.rs:156 (related: jix/src/ops/reduction/variance.rs:95-102 `update`, :127-151 `merge_states`)
- Reachability: public Rust API and Python API
- Reported by: found by hand while rebasing the hunt onto df2f918 (#92); no hunter run, so there was no write-up until this consolidation
- Consolidated: written for this report from KNOWN.md K108. Re-checked at main c705a54 (#107): still reproduces (repro_k108: var([1e308, -1e308, 0.0]) and var([1e308]*40 + [-1e308]*40) return NaN, numpy inf; the #107 merge fix of K166 does not cover Welford's update). Current location: jix/src/ops/reduction/variance.rs:154.

## What goes wrong
The variance of finite data whose squared deviations overflow f64 should be +inf, as in numpy.
For two elements jix returns inf (pinned by `var_std_overflowing_deviation_is_inf`), but from three
elements on it can return NaN: `var([1e308, -1e308, 0.0])` and
`var([1e308]*40 + [-1e308]*40)` are NaN. Before #92 both gave inf (K67); the K84 fix in #92, which
keeps a NaN m2 as NaN so that NaN / inf inputs give NaN, partly reverted that.

## Trigger
```python
jix.var(jix.asarray([1e308, -1e308, 0.0]))  # nan, numpy: inf (with an overflow warning)
jix.var(jix.asarray([1e308] * 40 + [-1e308] * 40))  # nan, numpy: inf
```

## Repro
`bug-hunt/report/repros/repro_k108.rs`. Copy it to `jix/tests/` and run
`cargo test --manifest-path jix/Cargo.toml --all-features --test repro_k108 -- --nocapture`.
It asserts inf and fails with:
```
var([1e308, -1e308, 0]) = NaN, var([1e308]*40 + [-1e308]*40) = NaN (numpy: inf, inf)
```

## Root cause
`finalize` (variance.rs:156) maps only `m2 < 0.0` to +inf and keeps a NaN m2. Welford's update
(variance.rs:95-102) reaches a NaN m2 from finite input: after 1e308 and -1e308 the running mean
overflows to -inf on the second item, then `0.0 - (-inf)` and `-inf + inf` make the mean and m2 NaN.
Chan's merge (:127-151) can do the same across lanes. The sign of m2 cannot tell this case from a
NaN or inf input (K84), so finalize has no way to choose between inf and NaN.

## Suggested fix
Track a flag in the state for "some input was non-finite" (set in update / update_bulk, OR-ed in
merge_states) and map a NaN m2 to +inf when the flag is clear. Alternatively, compute the mean with
a scaled update that cannot overflow for finite inputs.
