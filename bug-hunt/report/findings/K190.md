# K190: Setting one codec key in params (compression_level, codec or filters) resets the source's other codec settings to their defaults, while the docs promise unset keys are inherited

- Severity: low  Verdict: confirmed  Category: questionable-semantics
- Location: jix/src/storage/params.rs:233 (related: jix/src/storage/params.rs:182, 195, 212 (the
  three setters), jix/src/storage/params.rs:177-178 (the only doc that mentions the reset),
  jix/src/array/compact.rs:63-64 and :181, jix-py/src/array.rs:1684 (compact docstring),
  jix-py/src/array.rs:1859, 1866, 1879 (resolve_array_params), jix-py/src/archive.rs:202-203
  (write_array docstring))
- Reachability: Python API (`jix.compact`, `Array.compact`, `jix.write_array` of a lazy view) and
  public Rust API (`ArrayParams::level` / `filters` / `codec` + `compact_with` / `write_to`)
- Reported by: py-core-archive-params
- Consolidated: found in run 2026-11-16-scan-106-107 as F007; line numbers below are at c705a54 (#107). Re-run by hand at main c705a54 (#107): reproduces (repro_k190: 3 tests fail; K190.py: 4 unset codec keys not inherited). Current location: jix/src/storage/params.rs:233.

## What goes wrong
`ArrayParams` keeps the whole codec configuration in one `Option<EncoderParams>`. Each of
`codec()`, `level()` and `filters()` does `encoder_params.get_or_insert_with(EncoderParams::default)`
and then overwrites its own field, so setting one key materializes the other two at their defaults
(Zstd, level 3, `[ByteShuffle]`). `inherit_unset_from_storage` then inherits the encoder params only
as a whole (`get_or_insert_with(|| spec.encoder_params().clone())`), so once any codec key is set
nothing is taken from the source. The Python docs say the opposite, per key: `jix.compact` "Unset
keys are inherited from the source storage if `array` is a jix array", `write_array` "Unset fields
are inherited from the source array"; the Rust `compact_with` doc says "Fields not set in `params`
are inherited from the source storage", and `level()` / `filters()` say nothing about a reset. Only
`ArrayParams::codec`'s doc (params.rs:177-178) says "Setting any codec field materializes the codec
configuration to its defaults". Data still round-trips; the output silently uses a different
compression setup than requested and documented (in the trigger, 57x smaller or 39% larger).

## Trigger
Python:
```python
x = np.arange(1 << 16, dtype=np.int32)
src = jix.compact(x, params={"filters": [], "compression_level": 3})
jix.compact(src, params={"compression_level": 3})  # filters come back as ["byte-shuffle"]
jix.compact(src, params={"codec": "zstd"})  # the only valid codec, still resets filters
jix.write_array(src + 0, buf, params={"compression_level": 3})  # same through a lazy view
src19 = jix.compact(y, params={"compression_level": 19})
jix.compact(src19, params={"filters": ["byte-shuffle"]})  # level falls back to 3
```
Rust: `src.compact_with(ArrayParams::new().level(3)?, &ctx)` on a source built with
`ArrayParams::new().filters(&[])?`; likewise `.codec(Codec::Zstd)`, and `.filters(&[ByteShuffle])`
on a level-19 source.

## Root cause
The codec settings are one optional group (`encoder_params: Option<EncoderParams>`,
params.rs:91), but the user-facing surface exposes them as three independent keys. The setters
(params.rs:180-214) seed the group from `EncoderParams::default` instead of leaving the other keys
unset, and `inherit_unset_from_storage` (params.rs:232-233) fills only a wholly-unset group. The
design is recorded on `ArrayParams::codec` alone (since #55); `jix-py` `resolve_array_params`
(array.rs:1857-1880) calls the setters key by key, so the Python per-key promise
(array.rs:1684, archive.rs:202) cannot hold. Not a #106/#107 regression and not in KNOWN.md.
Note: arrays read from an archive take their codec settings from `read_array`'s `params`
(documented at jix-py/src/archive.rs:35-40), so for them the same reset applies to codec keys
given at read time.

## Suggested fix
Store the codec fields separately (`codec: Option<Codec>`, `level: Option<i8>`,
`filters: Option<ArrayVec<Filter, MAX_FILTERS>>`), have `inherit_unset_from_storage` fill each from
`spec.encoder_params()` independently, and build the `EncoderParams` after inheritance (missing
keys -> defaults only when there is nothing to inherit). Alternatively, if the group semantics are
intended, document them on `level()`, `filters()`, `compact_with`, and the Python `compact` /
`write_array` / `read_array` params docs ("setting any of codec / compression_level / filters
resets the others to their defaults"), and add a test that pins it.
