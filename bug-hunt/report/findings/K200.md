# K200: reshape / broadcast (and Array.reshape / Array.broadcast) accept a Python bool as a shape entry (True -> 1, False -> 0), unlike numpy and unlike jix's own dim and index arguments

- Severity: low  Verdict: confirmed  Category: questionable-semantics
- Location: jix-py/src/ops/shape_ops.rs:721 (related: jix-py/src/ops/shape_ops.rs:58, jix-py/src/array.rs:1399, jix-py/src/array.rs:1442, jix-py/src/type_hint.rs:94-109, jix-py/src/ops/shape_ops.rs:274, jix-py/python/tests/test_getitem.py:186-211)
- Reachability: Python API
- Reported by: py-ops-shape-ops
- Consolidated: found in run 2026-11-17-scan-106-107-b as F009; line numbers below are at c705a54 (#107). Re-run by hand at main c705a54 (#107): reproduces (K200.py: 6 of 6 checks fail, bool shape entries accepted). Current location: jix-py/src/ops/shape_ops.rs:721.

## What goes wrong
The shape argument of `jix.reshape`, `jix.broadcast`, `Array.reshape` and `Array.broadcast` is
`ItemOrTuple<i64>`. pyo3's `i64` extraction accepts a Python `bool`, so `True` silently means a
length-1 dim and `False` a length-0 dim. numpy raises TypeError for a bool shape entry in both
`reshape` and `broadcast_to`. jix also rejects bool everywhere else an integer stands for array
structure: every dim argument goes through `Dim`, which rejects bool on purpose (#93, "Dont accept
bools as `dim` argment", tested by `test_bool_dim_raises`), and basic indexing rejects bool items
(`test_bool_index_raises`). The shape entries are the one structural integer argument left out of
that policy. The worst case is `False`: `a.broadcast((False, 6))` returns an empty `(0, 6)` array
and raises nothing, where numpy raises. `repeat` / `tile` (repeats) and `roll` (shift) also accept
bool, but numpy does too, so they are not part of this finding.

## Trigger
```python
x = np.arange(6, dtype=np.int32)
a = jix.asarray(x)
jix.reshape(a, (True, -1))  # -> shape (1, 6)
jix.reshape(jix.asarray(np.int32(1)), True)  # -> shape (1,)
a.reshape((2, True, 3))  # -> shape (2, 1, 3)
jix.broadcast(a, (True, 6))  # -> shape (1, 6)
a.broadcast((False, 6))  # -> shape (0, 6), empty
```

## Root cause
#93 added the bool guard to the `Dim` newtype (type_hint.rs:94-109) and the index parser checks
`!item.is_instance_of::<PyBool>()` before `extract::<i64>()` (shape_ops.rs:274), but shape
entries are extracted as plain `i64` through `ItemOrTuple<i64>` (shape_ops.rs:58, 721;
array.rs:1399, 1442), so pyo3's int extraction (bool is an int subclass) lets them through. No
test covers a bool shape entry, and no doc or "Intentional behaviors" entry says it is meant.

## Suggested fix
Add a bool-rejecting shape-entry newtype next to `Dim` (e.g. `ShapeEntry(i64)` that raises
`TypeError("a shape entry must be an int, not a bool")`) and use `ItemOrTuple<ShapeEntry>` for the
four shape parameters; extend `test_bool_dim_raises` (or a sibling test) with `reshape` /
`broadcast` / `Array.reshape` / `Array.broadcast` cases.
