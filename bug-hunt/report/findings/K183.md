# K183: NumPy reductions (np.sum / mean / max / min / prod / std / var / all / any, np.squeeze(axis=)) raise "Array.sum() got an unexpected keyword argument 'axis'" on a jix.Array, while np.argmax / np.nanmax / np.median / np.average / np.round work through __array__

- Reachability: Python API

- Consolidated: found in run 2026-11-16-batch7-6 as F001; line numbers below are at that run's commit. Re-checked at main c705a54 (#107): still reproduces (K183.py: 13 numpy functions raise TypeError). Current location: jix-py/src/array.rs:1336.

## What goes wrong
`jix.Array` implements `__array__` (since #94), and its docstring calls it "the hook behind
`np.asarray(a)` and `np.array(a)`". It also has methods named `sum`, `mean`, `max`, `min`, `prod`,
`std`, `var`, `all`, `any` and `squeeze`, but they take jix keywords:
`(dim=None, *, keepdim=False[, ddof])`. For any object that is not exactly an `ndarray`, NumPy's
fromnumeric functions look the same-named method up first and call it with NumPy keywords. For
example, `_wrapreduction` calls `obj.sum(axis=None, out=None)`, and `np.mean` calls
`a.mean(axis=..., dtype=..., out=...)`. Every one of these calls therefore raises
`TypeError: Array.sum() got an unexpected keyword argument 'axis'`, even when the caller passed no
axis. The error names a jix method the user never called.

Functions that go through `_wrapfunc` catch that TypeError and fall back to `__array__`, so they
work: `np.argmax`, `np.round`, `np.repeat`, `np.reshape`, `np.clip`. Functions that call `asarray`
also work: `np.nanmax`, `np.median`, `np.average`, `np.cumsum`, `np.sort`. The surface is
therefore inconsistent: `np.max` fails while `np.nanmax` works, and `np.mean` fails while
`np.average` works.

Nothing is silently wrong. Every result that comes back is correct, including a probe of about 20
more functions. `np.squeeze(z)` returns a lazy `jix.Array` with the correct values. That is NumPy's
normal duck-type dispatch and is not a defect in itself, but `np.squeeze(z, axis=0)` raises the
same TypeError.

This is not covered by the documented intentional behaviors. `__array_ufunc__ = None`
(py-core.md) refuses ufuncs on purpose, but no doc or test says that `np.sum` and the other
fromnumeric reductions are unsupported. jix-py/docs/module.md:14 says "The library is
NumPy-compatible ... and materialize to NumPy arrays on demand".

## Trigger
```python
z = jix.compact(np.arange(6.0).reshape(2, 3))
np.sum(z)  # TypeError: Array.sum() got an unexpected keyword argument 'axis'
np.mean(z)
np.max(z)
np.amin(z)
np.std(z)
np.var(z)
np.prod(z)
np.all(z)
np.any(z)  # same
np.squeeze(jix.compact(np.zeros((1, 3))), axis=0)  # TypeError: Array.squeeze() ... 'axis'
np.nanmax(z), np.median(z), np.average(z), np.argmax(z)  # 5.0, 2.5, 2.5, 5 (work)
```

## Root cause
The reduction and squeeze methods at jix-py/src/array.rs:1264-1370 and 1441-1447 share NumPy's
method names but declare `#[pyo3(signature = (dim=None, *, keepdim=false ...))]`, so the keywords
NumPy passes (`axis`, `out`, `dtype`, `keepdims`, `where`) are rejected. NumPy treats an object
that has a method of that name as a duck array and does not fall back to `__array__` for
reductions. `_wrapreduction` (fromnumeric.py:66-83) and `mean`, `std`, `var` and `squeeze` have no
TypeError fallback; only `_wrapfunc` (48-63) has one. jix also does not define
`__array_function__`, which would let it take over these calls.

## Suggested fix
Pick one behavior and apply it consistently:
1. Define `__array_function__` to convert `jix.Array` arguments via `__array__` and call
   `func(*args, **kwargs)`. All `np.*` functions then work eagerly on ndarrays, and `np.squeeze`
   returns an ndarray as well.
2. Or accept NumPy aliases on these methods: `axis` as `dim`, `keepdims` as `keepdim`, and `out` /
   `dtype` / `where` only as `None`/default, raising a clear error otherwise. `np.sum(z)` then
   returns a lazy 0-d `jix.Array`.
3. At minimum, document that `np.*` reductions are unsupported and point users to `jix.sum(a)` /
   `np.sum(a.numpy())`.

Add a test to `test_array_protocol.py` for the chosen behavior.
