# F013: numpy(out=) accepts self-overlapping destinations (positive strides that alias), breaking StridedBuf::from_raw_parts_mut's no-alias precondition; reductions into such an out return values that belong to no output cell

- Severity: low  Verdict: confirmed  Category: wrong-result
- Location: jix-py/src/array.rs:266 (related: jix-py/src/array.rs:257-259, jix-py/src/array.rs:642, jix-py/src/array.rs:473, jix/src/storage/buf.rs:86, jix/src/ops/reduction.rs:500, jix/src/ops/reduction.rs:1097, jix/src/ops/reduction.rs:1164)
- Reachability: Python API (the Rust public API needs the unsafe `StridedBuf::from_raw_parts_mut`, whose contract forbids it, and ndarray's safe `ArrayViewMut` constructors reject aliasing)
- Reported by: py-core-read-path

## What goes wrong
`check_output_array` says the destination "must not map two different indices onto the same
byte" (array.rs:257-259), but its stride loop (array.rs:266-285) only rejects negative and zero
strides on dims longer than 1. A writeable view whose positive strides overlap passes. Examples are
`sliding_window_view(..., writeable=True)`, `as_strided`, and a stride smaller than the itemsize.
`numpy()` then passes it to `StridedBuf::from_raw_parts_mut` (array.rs:642), whose Safety section
(buf.rs:86-87) requires that no two indices share a byte. Plain copies and element-wise ops end
up last-write-wins, which is what NumPy gives too. Reductions differ. When the state and output
layouts match, they fold their running states straight into `out` (`state_in_out_buf`,
reduction.rs:500-514, and the early return at reduction.rs:1164-1171). Cells that share bytes
then fold each other's items into one slot, so the buffer holds sums and products that no output
cell has. NumPy buffers internal overlap and gives last-write-wins over the true per-cell
results. No memory-safety violation was found: every core access to `out` goes through one
pointer at a time, and the only `PtrMutNoalias` / `&mut` taken over `out` are one per tile or one
per element and are never live together.

## Trigger
```python
src = np.arange(1, 25, dtype=np.int64).reshape(2, 4, 3)
a = jix.compact(src)
buf = np.zeros(6, np.int64)
out = sliding_window_view(buf, 3, writeable=True)   # shape (4, 3), strides (8, 8)
a.sum(dim=0).numpy(out=out)
```
Also `as_strided(buf, (4, 3), (8, 8))` with `prod(dim=0)`. A complex64 `out` with stride 4,
smaller than its itemsize of 8, is accepted too. That case ends up last-write-wins, the same as
NumPy.

The jix sum explains itself. Slot 2 is shared by cells (0,2), (1,1) and (2,0). The first plane
seeds the slot, and the last seed, 7, wins. All three cells then add their second-plane item
into the same slot: 7 + 15 + 17 + 19 = 58.

## Root cause
The jix-py side establishes the no-alias precondition of `StridedBuf::from_raw_parts_mut` only
partly. `check_output_array` (array.rs:266-285) checks each stride on its own: sign, zero, and
alignment. It never checks the strides against each other or against the itemsize. Overlap
between dims, and an inner stride smaller than the itemsize, are both missed. The docstring
(array.rs:473-476) says "almost any strided view works" and lists only reversed and broadcast
views as rejected. The core relies on the precondition for read-modify-write use of `out`: a
reduction folds partial states into `out` at `out`'s strides (reduction.rs:1097-1134) and skips
finalization when state and output are the same buffer (reduction.rs:1164-1171). The bug is
low severity because the result is wrong only in a destination that cannot hold every cell's
result anyway, and no UB occurs today. It is still a latent hazard: if core code ever holds two
noalias pointers or `&mut` slices into `out` at the same time, this becomes UB reachable from
Python.

## Suggested fix
In `check_output_array`, take the dims with extent > 1 and sort them by stride. Require the
smallest stride to be >= itemsize, and each next stride to be >= stride * (extent - 1) +
itemsize of the dims before it. This is a sufficient non-overlap test, the same idea as
ndarray's `dim_stride_overlap`. Raise ValueError otherwise, or, to match NumPy, read into a
fresh temporary and `np.copyto(out, tmp)`. Document the rule in the `out` docstring next to the
reversed and broadcast cases.
