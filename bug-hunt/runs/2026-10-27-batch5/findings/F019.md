# F019: K58 fix is incomplete: check_out_buf still accepts a writable `out` whose strides alias over the requested region (InsertDim pull results, any pool-backed pull reused for a wider region), so push reads return Ok with the region not in out

- Severity: low  Verdict: confirmed  Category: questionable-semantics
- Location: jix/src/storage/buf.rs:307 `check_out_buf` (related: jix/src/ops/shape_ops/insert_dim.rs:188-194 the InsertDim pull relabel, which gives the inserted length-1 dims stride 0; jix/src/storage/buf.rs:413-415 `read_data_and_map_strides` keeps the buffer writable; jix/src/storage/buf.rs:349-367 `materialize_out_buf` and jix/src/util/mod.rs:153-167 `strides_for_layout_order`, which give pool pulls strides that only tile their own shape; jix/src/ops/shape_ops/broadcast.rs:157 and jix/src/storage/elementwise_pipeline.rs:955-958, the two K58 fixes; test jix/src/storage/buf.rs:446 `aliasing_pull_result_is_not_accepted_as_out`)
- Reachability: public Rust API (safe code only). Not reachable from Python, which never hands out a pull `StridedBuf` and rejects a 0 stride in `numpy(out=)`.
- Reported by: shape-ops-forwarders

## What goes wrong
K58 was fixed by making pull results read-only when their strides alias over THEIR OWN region
(Broadcast always, the pipeline when a collapsed dim is longer than 1). `check_out_buf` still checks
only stride count, writability and extent, not aliasing. A `StridedBuf` carries no shape, so a
writable pull result whose strides are fine for its own region can still alias over the larger
region of the next read it is passed to as `out`. Two sources: InsertDim's pull gives each inserted
length-1 dim stride 0 and keeps a pool buffer writable (no pool warm-up needed, the extent check
passes exactly), and any pool-backed pull reused for a wider region (packed strides `[8, 4]` used for
a `[2, 3]` region put (0, 2) and (1, 0) on byte 8; the pool can hand out a larger allocation, so the
extent check passes). The read returns `Ok` and later elements overwrite earlier ones, so `out` does
not hold the region. No UB: all writes stay in bounds and go through one pointer in order, as for K58.

## Trigger
```rust
let ctx = ReadContext::default();
let a = Array::plain_ndarray(array![1i32, 2, 3, 4])?.flip(0).insert_dim(0);
let mut out = a.to_ndarray_buf(&[0..1, 0..4], &ctx, None)?;   // strides [0, 4], writable, 16 bytes
let big = Array::plain_ndarray(array![[10i32, 11, 12, 13], [20, 21, 22, 23], [30, 31, 32, 33]])?;
big.to_ndarray_buf(&[0..3, 0..4], &ReadContext::default(), Some(&mut out))?; // Ok
```
Second: warm `ctx` with a 1000-element `flip` pull and drop it, then
`out = plain([[1i32, 2], [3, 4]]).flip(0).to_ndarray_buf(&[0..2, 0..2], &ctx, None)` (strides
`[8, 4]`, writable, 4000-byte allocation) and push `plain([[10i32, 11, 12], [20, 21, 22]])` over
`[0..2, 0..3]` into it: Ok.

## Root cause
Strides that do not alias only make sense relative to a shape, but the K58 fix (broadcast.rs:157,
elementwise_pipeline.rs:955-958 `make_readonly_if_aliasing`) tests aliasing against the pull's own
region only. Every writable pull buffer can be passed back as `out` of a read with another shape
(test buf.rs:428-443 does this on purpose), and `check_out_buf` (buf.rs:307-346) does not test
whether `out`'s strides alias over the region it is asked to hold. So the push contract ("write the
region into `dst` at `dst`'s own strides; `dst` must not be broadcast") cannot be met, yet the read
returns `Ok`.

## Suggested fix
Do approach (a) from K58 in `check_out_buf`: for the dims whose index range is longer than 1, sort
(stride, extent) by stride and require each stride >= the span of the smaller-stride dims plus
`itemsize` (0 strides fail this). It is O(ndim log ndim), covers every `read_data` impl and every
source, and returns `InvalidArgument`. It can reject a few exotic non-overlapping interleaved layouts,
which is acceptable. Making only InsertDim's pull read-only would not cover the packed case.
Alternatively, return every pull result read-only, so the only writable `StridedBuf` safe code
can get is one built with the unsafe `from_raw_parts_mut`, whose contract already forbids aliasing.
