# F012: asarray / compact / cast with dtype= silently wrap out-of-range Python ints (asarray(300, dtype=uint8) -> 44, compact([-1, 5], dtype=uint32) -> [4294967295, 5]), while every jix op bounds-checks Python ints and raises OverflowError

- Severity: low  Verdict: confirmed  Category: questionable-semantics
- Location: jix-py/src/ops/as_array.rs:60-65 (related: jix-py/src/ops/common/operand.rs:200-211, jix-py/src/ops/common/operand.rs:377, jix-py/src/ops/common/operand.rs:97, jix-py/src/ops/mod.rs:92-97, jix-py/src/array.rs:1631)
- Reachability: Python API (`jix.asarray(x, dtype=)`, `jix.compact(x, dtype=)`, `jix.cast(x, dtype)` with x a Python int or a (nested) list/tuple of Python ints)
- Reported by: py-ops-operand-broadcast

## What goes wrong
`asarray` converts `value` with no knowledge of the requested dtype, then applies a wrapping lazy
element cast. A Python int becomes an untyped i64 `Scalar` and a list of ints becomes an int64
numpy array (`np.asarray(value)` with no dtype), so the out-of-range check that jix applies to
every untyped Python int elsewhere (`Operand::cast` -> `check_int_in_bounds`) never runs. The
result is silent data corruption at array creation: `jix.compact([0, 255, 256], dtype=np.uint8)`
stores `[0, 255, 0]`. This goes against jix's own policy (#85, `test_python_int_out_of_bounds_raises`:
"an OverflowError is raised rather than silently wrapping the scalar"). `u8_arr + 256` and
`jix.where(c, u8_arr, -1)` raise. numpy 2 also raises for `np.asarray(300, dtype=np.uint8)` and
`np.array([0, 255, 256], dtype=np.uint8)`. Wrapping stays correct for TYPED sources (numpy
arrays / scalars, jix arrays): numpy's `np.asarray(np.int64(300), dtype=np.uint8)` also gives
44, and that is the documented `jix.cast` semantics. The defect is only that literal Python ints,
which have no source dtype, are treated as int64 values being cast.

## Trigger
- `jix.asarray(300, dtype=np.uint8)` -> `array(44, uint8)`
- `jix.asarray(-1, dtype=np.uint8)` -> `array(255, uint8)`
- `jix.compact([0, 255, 256], dtype=np.uint8)` -> `[0, 255, 0]`
- `jix.compact([-1, 5], dtype=np.uint32)` -> `[4294967295, 5]`
- `jix.compact(2**40, dtype=np.int32)` -> `array(0, int32)`
- `jix.asarray([[128]], dtype=np.int8)` -> `[[-128]]`
- `jix.cast(300, np.uint8)` -> `array(44, uint8)`

Related observation (the opposite direction, same root cause): `jix.asarray(2**63, dtype=np.uint64)`
raises `OverflowError: Python integer 9223372036854775808 out of bounds for int64`, although the
value fits the requested dtype and `np.asarray(2**63, dtype=np.uint64)` accepts it. The int is
range-checked against int64 (operand.rs:64-68) because the dtype is not yet known.

## Root cause
`asarray` (jix-py/src/ops/as_array.rs:60) calls `Operand::from_any_with_params(value, params,
false)`, which has no dtype parameter. Python ints become `Scalar::Int(i64), precision None`
(operand.rs:63-69). Lists go through `np_asarray.call1((value,))` with no dtype
(operand.rs:97), so numpy picks int64 and never range-checks. `asarray` then calls `cast_impl`
(as_array.rs:65, ops/mod.rs:105), which builds `Array::cast::<Dst>()`, a wrapping `as`-style
element cast. The untyped-int bounds check lives only in `Operand::cast` (operand.rs:209-211), and
the asarray path never calls it. `jix.compact(x, dtype=)` delegates to `asarray`
(array.rs:1631). `jix.cast` uses `asarray_simple` and then `cast_impl` (ops/mod.rs:92-97). Both
inherit the behavior. No test pins the wrapping for Python-int inputs. The `test_asarray_dtype_*`
tests in test_array_ops.py:43-76 only use in-range values or typed numpy sources.

## Suggested fix
Pass the requested dtype down for inputs that have no dtype of their own:
- For an untyped Python scalar (`Operand::Scalar` with `precision == None`) and a scalar target,
  use `Operand::cast(kind)` (runs `check_int_in_bounds`, builds the Scalar at the target dtype)
  instead of `cast_impl`.
- For inputs that are neither a jix Array, a numpy array nor an `np.generic` (lists, tuples,
  other array-likes), call `np.asarray(value, dtype=np_dtype)` so that numpy does its NEP 50
  range check. A struct / unsupported dtype still falls through to the existing errors.
- Keep the wrapping `cast_impl` for typed sources (jix arrays, numpy arrays and scalars), which
  matches numpy's astype / asarray of typed data.
- Optionally, for an explicit unsigned target, accept Python ints in (i64::MAX, u64::MAX].
