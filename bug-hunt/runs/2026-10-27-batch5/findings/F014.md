# F014: numpy(out=) with an empty out that has a negative stride on a dim of extent > 1 (or a huge stride) panics in debug builds: the stride rebuild runs before the empty early return and trips debug_assert!(read_shape[dim] <= 1) / a multiply overflow

- Severity: low  Verdict: confirmed  Category: panic (debug-only)
- Location: jix-py/src/array.rs:588-617 (the stride rebuild; the assert is at line 607, the C-order multiply at line 609) (related: jix-py/src/array.rs:251-255, where `check_output_array` returns Ok for any empty shape before the stride checks; jix-py/src/array.rs:619-622, the `nitems == 0` early return that comes after the rebuild)
- Reachability: Python API (`Array.numpy(out=...)` / `Array.numpy(index, out=...)` with an empty numpy `out` built by `np.lib.stride_tricks.as_strided` or `np.ndarray(..., strides=...)`)
- Reported by: py-core-read-path

## What goes wrong
`check_output_array` returns `Ok` for any `out` whose shape contains a 0 before it checks strides. Its comment assumes numpy reports all-zero strides for an empty array. That is true for arrays made by `np.empty` and by slicing: `np.empty((0, 3))[:, ::-1]` reports `(0, 0)`. It is not true for `as_strided` or `np.ndarray(strides=...)`, which keep the strides they are given. `numpy()` then rebuilds `to_ndarray_buf` strides from `out.strides()` before it reaches the `nitems == 0` early return. When it meets a negative stride, the rebuild assumes the earlier check guaranteed `read_shape[dim] <= 1` and `debug_assert!`s that. On an empty out, a dim of extent 3 with stride -8 fails that assert. The C-order replacement `strides[dim + 1] * read_shape[dim + 1]` is also unchecked: a negative stride on the empty dim, next to a dim with a huge (unchecked) stride, overflows. In debug builds, which is what `maturin develop` and the test setup produce, both raise `PanicException`. In release builds the assert is compiled out and the multiply wraps. The strides are never used, because the empty early return follows, so release correctly returns `out` unchanged. No memory is touched in either build.

## Trigger
```python
import numpy as np, jix
a = jix.compact(np.zeros((0, 3)))
a.numpy(out=np.lib.stride_tricks.as_strided(np.zeros(8)[4:], shape=(0, 3), strides=(24, -8)))
a.numpy(out=np.ndarray((0, 3), 'f8', buffer=np.zeros(8), offset=16, strides=(24, -8)))
jix.compact(np.zeros((3, 4))).numpy((slice(0, 0), slice(None)),
    out=np.ndarray((0, 4), 'f8', buffer=np.zeros(8), offset=24, strides=(32, -8)))
# same root cause, other panic: negative stride on the empty dim, huge stride on the next
a.numpy(out=np.ndarray((0, 3), 'f8', buffer=np.zeros(8), offset=16, strides=(-8, 2**63 - 8)))
```

The release-build behavior was not run, because it would need a separate release build of jix-py.
It follows from the code. `debug_assert!` is compiled out and the overflowing multiply wraps.
The resulting `strides` are only used after the `nitems == 0` check at line 620, which returns
`Ok(np_arr)` first. So release returns `out` unchanged and writes nothing.

## Root cause
The stride-rebuild comment at jix-py/src/array.rs:602-606 says "`check_output_array` rejected
negative strides on dims longer than 1". That is false for empty outs, because the
`out_shape.contains(&0)` early return at jix-py/src/array.rs:251-255 skips the stride checks
completely. Its own comment ("numpy reports all-zero strides for an empty array") holds only for
arrays numpy allocates or slices, not for `as_strided` / `np.ndarray(strides=)` views. The
rebuild (jix-py/src/array.rs:588-617) also runs before the `nitems == 0` early return
(jix-py/src/array.rs:619-622). For an empty selection those strides are never used, so the
asserted invariant does not matter there.

## Suggested fix
Compute `nitems` from `read_shape` and return `Ok(NdArray(np_arr))` before the stride rebuild,
which can stay unchanged. The `index` parse, `check_output_array` (dtype, shape and writeable
checks) and the allocation for `out=None` all happen earlier, so no validation is lost. An
alternative is to make the rebuild tolerate any stride when `nitems == 0`, but moving the early
return is simpler and also covers the overflow variant.
