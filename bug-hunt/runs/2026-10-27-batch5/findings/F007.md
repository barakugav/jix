# F007: Broadcast reads and evaluates its inner row for an EMPTY request (broadcast dim 0..0 becomes inner 0..1), so zero-element reads raise spurious arithmetic errors, do O(row) work, or abort

- Severity: medium  Verdict: confirmed  Category: error-handling
- Location: jix/src/ops/shape_ops/broadcast.rs:137-144 (related: jix/src/ops/shape_ops/insert_dim.rs:171-181, jix/src/ops/shape_ops/concatenate.rs:221 and 250-291, jix/src/array.rs:680-683)
- Reachability: public Rust API (any empty read of a Broadcast whose only empty ranges are on broadcast dims) and Python API (through `jix.concatenate`, with a zero-length broadcast member that is not the first or last member)
- Reported by: shape-ops-forwarders

## What goes wrong
`Broadcast::read_data` maps every broadcast dim to the inner range `0..1` and pulls the inner
region before it checks whether the request is empty. If every empty range in the request is on a
broadcast dim (a broadcast to length 0, or an empty sub-range such as `2..2` of a broadcast dim),
the inner region it reads is not empty. The whole inner row gets materialized and evaluated, then
nothing is copied. As a result:

1. An arithmetic error in data that is not part of the zero-element result fails the read. Example: `Err(Arithmetic: divide by zero)` from `to_ndarray()` on an array with no elements.
2. The read costs as much as the full inner region (decompression, op evaluation, allocation).
3. A huge lazy inner row aborts the process when it fails to allocate.

The other shape forwarders do not have this problem. InsertDim short-circuits empty reads, and
Slice, PermuteDims, RemoveDim and direct empty sub-reads of the same pipeline return Ok without
evaluating anything. The behavior also contradicts `to_ndarray_sub`'s doc ("only the
corresponding region of the innermost storage is read", array.rs:680-683). It makes results
depend on read path and position:
- `.compact()` of the same array succeeds while `.to_ndarray()` fails.
- `concatenate([o, o, empty])` works, but `concatenate([o, empty, o])` fails.

## Trigger
Rust, with `q = plain([[6i32, 7, 8]]) / plain([[2i32, 0, 4]])` (element [0, 1] divides by zero, Error mode by default):
- `q.broadcast(&[0, 3]).to_ndarray::<IxDyn>()` returns `Err("divide by zero encountered")`. Expected: `Ok` with shape `[0, 3]`.
- `q.broadcast(&[5, 3]).to_ndarray_sub::<IxDyn>(&[2..2, 0..3], &ctx)` returns the same `Err`.
- `jix::ops::concatenate((ones(2,3), q.broadcast(&[0, 3]), ones(2,3)), 0).to_ndarray()` returns the same `Err`. Expected: a 4x3 array of ones.
- `compact([[1u8]]).broadcast(&[1, 1 << 50]).flip(1).broadcast(&[0, 1 << 50])`, read with an empty request: `memory allocation of 1125899906842624 bytes failed`, SIGABRT.

Python, with `q = a // b` (b holds a 0) and `o = ones((2, 3))`:
- `jix.concatenate([o, jix.broadcast(q, (0, 3)), o]).numpy()` raises `FloatingPointError: divide by zero encountered`.
- Implicit broadcasting hits the same path: `q + zeros((0, 3))` has shape (0, 3), and `jix.concatenate([o, q + zeros((0, 3)), o]).numpy()` raises the same error.

The error needs a non-empty outer read that reaches a member with an empty range. Python's
`numpy()` returns early for an empty array (jix-py/src/array.rs:620), so `jix.broadcast(q, (0, 3)).numpy()` on its own is OK. Concatenate supplies the non-empty outer read: it returns
early only when the whole output is empty (concatenate.rs:221). Otherwise it reads every member
whose start is below the request end, so a zero-length member in the middle is read with local
range `0..0` (concatenate.rs:250-291). A zero-length member at the end is never read.

## Root cause
broadcast.rs:137-143 builds `inner_index` with `0..1` on every broadcast dim, whatever the
requested range on that dim is. broadcast.rs:144 then pulls the inner region unconditionally. When
`index[d]` is empty on a broadcast dim `d`, the output region is empty, but the inner region
`[0..1 on broadcast dims, index[d] elsewhere]` is not. Nothing in the read path checks for an
empty region before evaluating. InsertDim handles the same situation explicitly, in its
`transform_index` and `read_data` (insert_dim.rs:136-147 and 171-181). Broadcast has no
equivalent.

## Suggested fix
At the top of `Broadcast::read_data`, after `check_out_buf`: if any `index[d]` is empty, return
`materialize_out_buf(out, context, out_shape, dtype, layout_order)` without reading the inner
(the same as InsertDim and Concatenate). Another option is to map an empty range on a broadcast
dim to inner `0..0` instead of `0..1`, which forwards the empty read like Slice does. A regression
test is the repro above.
