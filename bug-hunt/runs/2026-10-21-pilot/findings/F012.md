# F012: ArrayParams::block_shape / block_shape_fixed_dims unwrap check_ndim, so a params list with more than 8 entries panics (PanicException from Python) instead of returning an error

- Severity: low  Verdict: confirmed  Category: error-handling
- Location: jix/src/storage/params.rs:121 (related: jix/src/storage/params.rs:140, jix-py/src/array.rs:1663-1668, jix-py/src/array.rs:1620 resolve_array_params, reached from jix-py/src/array.rs:1604 `compact`, jix-py/src/ops/as_array.rs:59 `asarray`, jix-py/src/archive.rs:99 `read_array`, jix-py/src/archive.rs:206 `write_array`)
- Reachability: Python API (any `params=` dict) and public Rust API (`ArrayParams::block_shape`, `ArrayParams::block_shape_fixed_dims`)
- Reported by: util-memory-arrayvec-bitmap-cache

## What goes wrong
The public builder setters `ArrayParams::block_shape` and `ArrayParams::block_shape_fixed_dims`
call `check_ndim(len).unwrap()`, so a slice longer than `NDIM_MAX = 8` panics. Neither setter
documents a panic, and the rest of the params validation is Result-based (`ArrayParams::tune`,
params.rs:299-320, returns `InvalidArgument` for a wrong-length block shape and documents
`TooManyDimensions` for ndim > 8). The Python params extractor passes the user's lists straight to
these setters, so `params={"block_shape": [1]*9}` surfaces as `pyo3_runtime.PanicException`, a
`BaseException` subclass that `except Exception` does not catch. Every neighbouring invalid-params
case in the same function raises a normal exception (ValueError for `read_size`, RuntimeError for a
wrong-length block shape), and jix-py/python/tests/test_bad_input.py states the project's intent
that malformed arguments raise instead of panicking. No memory-safety impact: the panic fires
before the `DimArray::from_slice` / `collect` that would otherwise also panic.

## Trigger
Python: `jix.compact(np.zeros((3, 5), np.float32), params={"block_shape": [1]*9})`, or
`params={"block_shape": [1, 1], "block_shape_fixed_dims": [True]*9}`; same via `jix.asarray`,
`jix.read_array`, `jix.write_array`.
Rust: `ArrayParams::new().block_shape(&[1u32; 9])` or `.block_shape_fixed_dims(&[true; 9])`.

## Root cause
The setters store into fixed-capacity `DimArray` / `DimBitmap` (capacity 8), so they must reject
longer inputs, but they do it with `.unwrap()` (params.rs:121, :140) in an infallible
`&mut Self`-returning builder instead of deferring the check to the fallible `tune()`. The Python
side (jix-py/src/array.rs:1663-1668) assumes the setters cannot fail and does no length check of
its own, unlike `read_size` at :1673.

## Suggested fix
Either validate the lengths in `resolve_array_params` and return `PyValueError` before calling the
setters (minimal, Python-only), or make the Rust setters non-panicking: store the raw length /
an error flag (or return `Result<&mut Self>`) and report `TooManyDimensions` from `tune()`. At the
least, document the panic on the Rust setters.
