# F018: `StridedBuf::from_raw_parts(_mut)` Safety sections are incomplete: a null pointer for an empty region, and an `out` over the same bytes as a `Plain` input, both meet the documented contract yet are UB

- Severity: low  Verdict: confirmed  Category: unsound-api
- Location: jix/src/storage/buf.rs:59-62 and :77-82 (doc), used at buf.rs:71 and :91 (related: jix/src/util/mod.rs:109-118, jix/src/storage/plain.rs:415-421, jix/src/storage/plain.rs:476-481, jix/src/storage/buf.rs:179 and :229-239, jix/src/util/nd_copy.rs:230, jix/src/array.rs:860-942 (`to_ndarray_buf` docs), jix-py/src/array.rs:473-485 (the Python-side rule, K31))
- Reachability: public Rust API (unsafe constructors, used as documented)
- Reported by: storage-core-buf-contract

## What goes wrong
The two public unsafe constructors only require `data` to be "valid for reads (and writes)
according to the shape, strides and itemsize" for `'a`, plus non-aliasing strides for `_mut`.
Internally they build a `&'a [u8]` / `&'a mut [u8]` with `slice::from_raw_parts(_mut)`, which
needs two more things the docs never state:
1. **Non-null, even at length 0.** `strided_span_bytes` returns 0 when any dim is 0
   (util/mod.rs:112-114). In Rust's own definition a 0-byte access is valid through any pointer,
   null included, so `from_raw_parts(null, &[0], ..)` meets the jix contract. But
   `slice::from_raw_parts` requires a non-null pointer, so the call is UB. A debug build aborts.
2. **Exclusive access for `'a`.** Nothing says the bytes must not be read or written through any
   other pointer while the `StridedBuf` lives. Nothing says an `out` must not overlap memory read
   by an input of the read. An in-place op (`out` over the bytes of a `Plain` from the unsafe
   `plain_ndarray_ptr`, whose own Safety section also allows this) meets every documented
   requirement. Yet jix then holds a `&mut [u8]` (the `out`) and a `&[u8]` (Plain pull or
   push, plain.rs:476) over the same bytes, and feeds them to `PtrNoalias`/`PtrMutNoalias` and
   `copy_nonoverlapping`. That is UB, and a debug build aborts on the identity case. The rule is
   documented for Python `numpy(out=)` (#87, K31) but nowhere on the Rust side: not in
   `from_raw_parts_mut`, `to_ndarray_buf`, `read_data` or `plain_ndarray_ptr`.

Side note (not demonstrated as UB): the `_mut` aliasing wording ("no two different indices
result in the same byte offset") permits partially overlapping elements (stride < itemsize).
I found no noalias reliance on that, since all writes go through one `PtrMutNoalias`. So it only
gives order-dependent values, and it is a wording fix.

## Trigger
(1) `unsafe { StridedBuf::from_raw_parts(std::ptr::null(), &[0], &[4], 4) }` (same with
`from_raw_parts_mut(null_mut(), ..)` used as `out` of an empty `to_ndarray_buf(&[0..0], ..)`).

(2) `buf = vec![1.0f32, 2., 3., 4., 5.]`, `p = buf.as_mut_ptr().cast::<u8>()`.
`a = plain_ndarray_ptr(p, [5], &[4], f32::DTYPE, ..)`.
`out = StridedBuf::from_raw_parts_mut(p, &[5], &[4], 4)`.
Then either `a.to_ndarray_buf(&[0..5], &ctx, Some(&mut out))` (identity, len 5) or
`(-a.view()).to_ndarray_buf(&[0..4], &ctx, Some(&mut out))` with 4 elements.

## Root cause
buf.rs:71/91 forward the caller's pointer to `slice::from_raw_parts(_mut)` but copy only part of
those functions' safety requirements into jix's own `# Safety` text. The non-null requirement
(it holds even for len 0) and the no-other-access-for-`'a` requirement are dropped. The internal
code then depends on both. The `&mut [u8]` is reborrowed in `data_mut` (buf.rs:179), and `out`
and inputs become `PtrMutNoalias`/`PtrNoalias` (buf.rs:229-239, elementwise pipeline), on the
assumption that they never overlap.

## Suggested fix
- In `from_raw_parts(_mut)`, use `NonNull::dangling()` when the span is 0, or document "non-null
  even for an empty region".
- Add to both Safety sections the exclusivity rule from `slice::from_raw_parts(_mut)`:
  - `_mut`: the bytes are not accessed through any other pointer for `'a`.
  - shared: not mutated for `'a`.
- State explicitly that an `out` must not overlap memory that any array in the lazy chain reads
  (e.g. a `Plain` built with `plain_ndarray_ptr`/`plain_ndarray_ref` over the same buffer).
  Mirror the rule in `to_ndarray_buf`/`read_data`, as #87 did for Python.
- Reword the aliasing clause as "no two distinct elements' byte ranges overlap".
