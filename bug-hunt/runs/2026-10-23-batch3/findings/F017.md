# F017: Writable pull results with aliasing 0 strides (Broadcast, elementwise pipeline) break the from_pool/with_strides no-aliasing contract, and check_out_buf accepts them back as `out`

- Severity: low  Verdict: confirmed  Category: questionable-semantics
- Location: jix/src/ops/shape_ops/broadcast.rs:156 (related: jix/src/storage/elementwise_pipeline.rs:885 and :943 `materialize_pipeline_out_buf` / `pick_output_layout`, jix/src/storage/buf.rs:282 `check_out_buf`, jix/src/storage/buf.rs:131 `from_pool` and :208 `with_strides` contracts, jix/src/ops/reduction.rs:496 `state_in_out_buf`, jix-py/src/array.rs:266-279 the Python `out=` check that does reject 0 strides)
- Reachability: public Rust API (safe code only). Not reachable from Python: `numpy(out=)` rejects a 0 stride on a dim longer than 1 (jix-py/src/array.rs:275-279).
- Reported by: storage-core-buf-contract

## What goes wrong
Two pull paths hand safe code a WRITABLE `StridedBuf` (a `PoolBuf`) whose strides alias: a 0 stride
on a dim longer than 1. Broadcast relabels the inner pull buffer with 0 strides on its broadcast dims
(`with_strides`, broadcast.rs:156), and that buffer is writable whenever the inner materializes (Flip,
elementwise ops, Compact...). The elementwise pipeline's own pull buffer gets stride 0 on every dim
where all operands have stride 0 (`pick_output_layout`, elementwise_pipeline.rs:943, then `from_pool`
at :885). Both break the documented safety contract of `from_pool` / `with_strides` ("no two indices
map to the same byte offset"). `check_out_buf` checks stride count, writability and extent, but not
aliasing, so such a buffer is accepted back as `out` of any push read. The read returns `Ok` and
writes many elements onto the same bytes, so `out` does not hold the region: Plain/Neg pushes keep the
last element per aliased slot, and a reduction (with `state_in_out_buf`) shares one state between
distinct output cells. Miri reports no UB today, because all writes go through one `PtrMutNoalias`
sequentially. Any future code that relies on non-aliasing `out` for soundness would make this safe-API
UB. Python already rejects such an `out`; Rust does not.

## Trigger
```rust
let ctx = ReadContext::default();
let b = Array::plain_ndarray(array![[1.0f32], [2.0]])?.flip(0).broadcast(&[2, 4]);
let mut out = b.to_ndarray_buf(&[0..2, 0..4], &ctx, None)?;   // strides [4, 0], writable
let x = Array::plain_ndarray(array![[1.0f32, 2., 3., 4.], [5., 6., 7., 8.]])?;
let ctx2 = ReadContext::default();
x.view().to_ndarray_buf(&[0..2, 0..4], &ctx2, Some(&mut out))?; // Ok, 8 elements onto 2 slots
```
Same with `-Array::plain_ndarray(array![[1.0f32]])?.broadcast(&[2, 4])`. Its pull gives strides
[0, 0], writable. Same with `x.view().sum(1)` pushed into a `[2]`-shaped out with strides [0].

## Root cause
`with_strides` and `from_pool` are `pub(crate) unsafe` and require non-aliasing strides
(buf.rs:125-131, 202-208). Broadcast's pull branch (broadcast.rs:156) and `materialize_pipeline_out_buf`
(elementwise_pipeline.rs:876-885) call them with 0 strides on dims longer than 1, and the buffer keeps
its writable `PoolBuf` variant. The public pull API then exposes it as writable (`data_ptr_mut()` is
`Some`), and `check_out_buf` (buf.rs:282-327) accepts it as `out`. That check was hardened for extent in
c009869 (K14), but not for aliasing, although the K14 write-up suggested it. The push contract
("write the region into `dst` at `dst`'s own strides") cannot be met for such a `dst`, but the read
still returns `Ok`.

## Suggested fix
Either (a) reject aliasing `out` in `check_out_buf`: a 0 stride on any dim whose index range has
length > 1 is an `InvalidArgument`, as jix-py already does. This is O(ndim) and covers every
`read_data` impl. Or (b) stop handing out writable aliasing pull buffers: make Broadcast's pull
relabel produce a read-only view (e.g. a `with_strides_readonly` that converts to the `Slice` variant
or marks the buffer read-only), and do the same for pipeline pull buffers with degenerate dims. (a)
is simpler and also guards against future sources. Also fix the `with_strides`/`from_pool` docs (or
the callers) so the crate does not break its own unsafe contracts.
