# F004: Plain/compact construction from an ndarray with negative strides (reversed views): `s as usize * size_of::<T>()` wraps the stride. Debug panics; release returns wrong windows and violates `from_raw_parts` / `get_unchecked` preconditions from safe code. The owned variant panics on `unwrap`.

- Severity: high  Verdict: confirmed  Category: wrong-result
- Location: jix/src/storage/plain.rs:289 (related: jix/src/storage/plain.rs:248, jix/src/storage/plain.rs:461-476, jix/src/util/mod.rs:109-118, jix/src/util/mod.rs:721 via jix/src/util/nd_copy.rs:144, jix/src/array.rs:274, jix-py/src/ops/common/operand.rs:172-176)
- Reachability: public Rust API (`Array::plain_ndarray_ref(_with)`, `Array::plain_ndarray_view(_with)`, `Array::compact_ndarray(_with)`, `Array::plain_ndarray(_with)`). Python is not affected: it rejects negative strides with ValueError.
- Reported by: dynamic-rust-differential (two reports: plain.rs:289 and plain.rs:248)

## What goes wrong
`StridedBuf`/`Plain` strides are unsigned, so the model has no negative strides. The safe
ndarray constructors never reject or normalize them, though. `plain_ndarray_ref_impl` converts
each signed ndarray stride with `s as usize * size_of::<T>()`. A reversed axis (`s![..;-1]`,
`invert_axis`, `flipud`) therefore becomes a stride of `2^64 - k*itemsize`.
- Debug builds: the multiply panics at construction.
- Release builds: `Plain::read_data` does all its span and offset math with wrapping arithmetic.
  - If the wrapped span `sum(stride*(len-1)) + itemsize` comes out to exactly 0, the `src_span == 0`
    branch (plain.rs:468) uses the BASE pointer and drops the window's start offset. The read
    then silently returns the window anchored at logical element 0.
  - Otherwise the span is a huge number and goes to `slice::from_raw_parts` with
    len > isize::MAX (UB). The values happen to come out right because the wrapped offsets act
    as negative offsets.
  - In the span-0 case, NdCopier then reads past a zero-length source slice through
    `get_unchecked` (UB).
- The owned constructor `plain_ndarray_with` uses `usize::try_from(s).unwrap()` (plain.rs:248)
  instead, so it panics in every build. That includes a length-1 axis with a negative stride,
  which ndarray reports as standard layout.

The doc comment of `plain_ndarray_ref` promises "Any layout supported by ndarray ... is handled
correctly", and the Errors sections mention only ndim. The Python binding rejects negative
strides explicitly (operand.rs:172-176). So the missing Rust-side check is an oversight, not a
design choice.

## Trigger
- `let base = array![1i32, 2, 3, 4]; let a = Array::plain_ndarray_view(base.slice(s![..;-1]))?;`
  then `a.to_ndarray_sub::<Ix1>(&[1..3], &a.read_ctx())`.
  - Strides: `[2^64-4]`; span = `(2^64-4)*1 + 4 = 0`.
- flipud matrix: `base = array![[1i32,2,3],[4,5,6],[7,8,9]]`,
  `Array::plain_ndarray_view(base.slice(s![..;-1, ..]))?.slice((1..3, 0..3)).to_ndarray::<Ix2>()`.
  - Strides: `[-12, 4]`; span = `-12 + 8 + 4 = 0`.
  - In general, any window of 2 full rows of a row-reversed C-order matrix, starting at row >= 1,
    hits this.
- Full read of the same reversed 1-d view, or `Array::compact_ndarray(&base.slice(s![..;-1]))`:
  the span is `2^64-8`, and `from_raw_parts` is called with len > isize::MAX.
- Owned: `let mut a = Array2::<i32>::from_shape_vec((1, 3), vec![1, 2, 3])?; a.invert_axis(Axis(0)); Array::plain_ndarray(a)`
  panics with `TryFromIntError(NegOverflow)`.

## Root cause
- plain.rs:289 (`s as usize * size_of::<T>()`) and plain.rs:248 (`usize::try_from(s).unwrap()`)
  assume ndarray strides are non-negative, but ndarray allows negative strides through ordinary
  safe operations.
- `Plain::new` (plain.rs:116) is the only place that could catch a bad stride. Its safety contract
  mentions only readability, and it never validates.
- `Plain::read_data` (plain.rs:461-476) then trusts the strides for:
  - `strided_span_bytes` (util/mod.rs:109-118, unchecked products);
  - the `src_span == 0` shortcut, meant for empty regions but also taken when a wrapped span
    happens to be 0;
  - `ptr.add(in_offset)`;
  - `from_raw_parts`.

## Suggested fix
Pick one in the three ndarray constructors (`plain_ndarray_with`, `plain_ndarray_ref_impl`, and
through it `compact_ndarray_with`):
- Reject negative strides with `InvalidArgument`, like jix-py does.
- Normalize them: for each axis with a negative stride, move the base pointer to the
  lowest-address element (`ptr + (len-1)*stride`) and wrap the array in a lazy flip. Plain alone
  cannot express a flip.

Either way:
- A length-1 (or length-0) axis with a negative stride should be normalized to stride 0 instead
  of rejected, because ndarray treats such arrays as standard layout.
- Separately, `Plain::read_data`'s empty-region shortcut should test for an empty `out_shape`
  directly instead of `src_span == 0`.
