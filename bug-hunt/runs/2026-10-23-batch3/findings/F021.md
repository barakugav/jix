# F021: Empty float / complex sum returns -0.0 (sign bit set) instead of +0.0

- Severity: low  Verdict: confirmed  Category: questionable-semantics
- Location: jix/src/ops/reduction.rs:1482-1483 (related: jix/src/ops/reduction.rs:2422-2428 `SumKernel::init_state`, jix/src/ops/reduction.rs:1260-1269 `finalize_states_empty_inner_loop`, jix/src/ops/reduction.rs:2381 doc "An empty reduction ... returns `0`", jix-py/src/ops/reduction.rs:286 same doc on the Python side)
- Reachability: public Rust API and Python API (`jix.sum` on any zero-length reduced dim)
- Reported by: dynamic-rust-differential

## What goes wrong
If any reduced dim has length 0, `sum` writes `-0.0` to every output cell for f16, f32 and f64. For
Complex<f32> and Complex<f64> it writes `(-0.0, +0.0)`. NumPy, and the "returns 0" the docs
promise, give `+0.0`. The two compare equal under IEEE `==`, but the sign bit is observable:
`1/x` gives `-inf` instead of `+inf`, `signbit`/`copysign`/`atan2` disagree, and the result prints
as `-0.`. Integer and bool sums are unaffected because their cast of -0.0 is 0. Non-empty sums are
also correct: -0.0 is the true additive identity, so a sum of `-0.0`s stays `-0.0` and a sum of
`+0.0`s gives `+0.0`. Only the empty path exposes the seed value.

## Trigger
Rust: `Array::compact_ndarray(&Array2::<f64>::zeros((3, 0)))?.sum(1).to_ndarray::<Ix1>()` gives
`[-0.0, -0.0, -0.0]`. The same happens with f32, f16 or Complex<f64>, and when reducing all dims
of an empty 1-d array.
Python: `jix.sum(jix.asarray(np.zeros((3, 0))), dim=1)` gives `[-0., -0., -0.]` where numpy gives
`[0., 0., 0.]`.

## Root cause
`impl_sum!` makes `Sum::init()` return `cast(-0.0)` (reduction.rs:1482-1483). -0.0 is the right
fold identity, because `-0.0 + x == x` for every x, including x = -0.0.
`SumKernel::init_state` (reduction.rs:2422-2428) returns `init()` unchanged when it gets `None`.
The only `init_state(None)` call is in the empty-reduction path,
`finalize_states_empty_inner_loop` (reduction.rs:1266), and it writes
`finalize_state(init(), 0) = init()` to every cell. So the empty sum returns the fold identity
-0.0 instead of the "empty sum" value +0.0.

## Suggested fix
In `SumKernel::init_state`, return `+0.0` for `None`, for example via a new
`Sum::empty() -> Output { cast(0.0) }`. Keep `init()` as `-0.0` for the `Some(item)` seed. The
`None` arm is reached only at reduction.rs:1266, so non-empty sums are unchanged. Add an empty
float/complex sum case to the tests that checks bits, not `==`.
