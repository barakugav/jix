# F007: Op2::shape calls the left child's shape() twice inside #[inline(always)], so debug builds inline 2^k copies for a left-deep chain of k binary ops: a 12-term sum overflows a 2 MiB thread stack (SIGABRT) and compile time / rustc memory grow exponentially

- Severity: medium  Verdict: confirmed  Category: resource
- Location: jix/src/ops/op2.rs:186 (related: jix/src/storage/mod.rs:290-292, jix/src/ops/cmp.rs:501-503, jix/src/array.rs:521-529, jix/src/array.rs:765, jix/src/ops/op2.rs:110)
- Reachability: public Rust API (any left-deep chain of `+ - * / & | ^`, comparisons, `map2`, `approx_eq`; not Python, whose arrays are type-erased)
- Reported by: concept-composition

## What goes wrong
`Op2::shape` (op2.rs:184-188) is `#[inline(always)]` and its body is
`debug_assert_eq!(self.a.shape(), self.b.shape()); self.a.shape()`, so with debug assertions on it
calls the left child's `shape()` twice. Every wrapper (`Add`, `Mul`, ... via
`impl_array_storage_forward!`, storage/mod.rs:290-292; the swapped comparisons, cmp.rs:501-503;
`Array::shape` / `Array::ndim`, array.rs:521-529) forwards `shape()` with `#[inline(always)]` as well.
LLVM's always-inliner runs at -O0, so each call site gets its own copy of the whole subtree, and -O0
does not merge stack slots. For a left-deep chain `a0 + a1 + ... + ak` (which is what Rust's
left-associative operators build) the inlined code and the frame of every function that calls
`shape()` on it grow as T(k) = 2 T(k-1) + c. Affected callers include `Array::to_ndarray_sub`
(`check_get_range(self.shape(), ..)`, `self.ndim()`) and each level's `Op2::read_data`
(`check_out_buf(.., self.shape(), ..)`). Debug is the default profile for `cargo test` / `cargo
build` / `cargo run`, so an ordinary 12-term sum or a degree-6 Horner polynomial aborts with a stack
overflow on a default 2 MiB thread (std::thread and the test harness), and expressions of 16-17
terms run rustc out of memory. Release builds are unaffected (the assert is compiled out).

## Trigger
Debug build. Twelve `Compact` i64 arrays of shape [3, 4];
`let v = a[0].view() + a[1].view() + ... + a[11].view(); v.to_ndarray::<IxDyn>()` on a
`std::thread::spawn` thread. Same for
`(((((c6*x + c5)*x + c4)*x + c3)*x + c2)*x + c1)*x + c0` (12 Op2 levels, alternating Mul/Add).

## Repro
`jix/tests/repro_2026_10_29_batch6__f007.rs` (aborts the process while the bug exists; run each test
by name):

```
cargo test --manifest-path jix/Cargo.toml --all-features --test repro_2026_10_29_batch6__f007 -- --exact left_deep_sum_of_12_terms_on_default_thread
cargo test --manifest-path jix/Cargo.toml --all-features --test repro_2026_10_29_batch6__f007 -- --exact horner_degree_6_on_default_thread
```

Both print `thread '<unknown>' has overflowed its stack / fatal runtime error: stack overflow,
aborting` (SIGABRT). With `--release` both pass.

Minimum thread stack (bisected with the `#[ignore]`d `stack_probe` test in the same file, each chain
in its own closure; 47 KB is the harness baseline):

| terms | left `.shape()` | left `to_ndarray` | right `to_ndarray` |
|------:|----------------:|------------------:|-------------------:|
| 8     | 115 KB          | 363 KB            | 155 KB             |
| 10    | 403 KB          | 1075 KB           | 191 KB             |
| 12    | 1563 KB         | 3811 KB           | 231 KB             |

The right-deep `.shape()` stays at 47 KB for every length. In the debug test binary the out-of-line
`Add<..11 levels..>::shape` is 0x171214 bytes (1.5 MB) of machine code, `to_ndarray_sub` for the
12-term sum is 3.0 MB and for the Horner polynomial 6.0 MB; the binary is 242 MB.

Compile cost of a test that only calls `.shape()` on the chain (rustc alone, non-incremental, max
RSS): left 8 terms 0.9 s / 236 MB, 10 terms 2.0 s / 313 MB, 12 terms 5.1 s / 807 MB, 14 terms
19.7 s / 2987 MB; right 14 terms 1.0 s / 249 MB. That is ~3.7x per two terms, so 16-17 terms need
roughly 11-21 GB (the hunter saw rustc SIGKILLed at 17 terms on a 15 GB machine; not re-run here to
avoid OOMing the shared machine).

Root cause check: a scratch copy of the crate with only the change in
`bug-hunt/runs/2026-10-29-batch6/repros/F007_probe_fix.diff` (bind `self.a.shape()` once, assert
against it) makes both repro tests pass in a debug build. Left-deep needs then match right-deep
(8/10/12 terms: 147/187/223 KB; `.shape()` alone 47 KB). The 14-term compile drops to 1.1 s / 246 MB,
and the test binary shrinks from 242 MB to 108 MB.

## Root cause
op2.rs:186-187 evaluates `self.a.shape()` twice (once in `debug_assert_eq!`, once as the return
value) in a function forced inline everywhere, recursively through the left operand. The assert is
also redundant: `Op2::new` (op2.rs:41-51) already rejects mismatched shapes and the shapes never
change after construction.

## Suggested fix
Evaluate the left shape once (`let s = self.a.shape(); debug_assert_eq!(s, self.b.shape()); s`), or
drop the `debug_assert_eq!` because `Op2::new` already checks it. That keeps the inlined cost linear
in chain length. Optionally also audit other `#[inline(always)]` methods that recurse into a child
more than once.
