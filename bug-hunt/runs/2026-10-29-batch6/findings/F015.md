# F015: compact_with / override_from_array silently replace a caller's block_shape_fixed_dims with the source's when block_shape is unset (compact_ndarray_with rejects the same params, archive reads honor them)

- Severity: low  Verdict: confirmed  Category: questionable-semantics
- Location: jix/src/storage/params.rs:303 (related: jix/src/storage/params.rs:288-290, jix/src/storage/params.rs:254, jix/src/storage/params.rs:351-355, jix/src/array.rs:1198, jix/src/array.rs:277, jix/src/array.rs:1315, jix/src/archive/array.rs:546-560, jix-py/src/array.rs:1584, jix-py/src/array.rs:1679)
- Reachability: public Rust API (`ArrayParams::override_from_array`, `Array::compact_with`, `write_to_with` and its variants) and Python API (`jix.compact` / `write_array` on a jix array)
- Reported by: storage-compact-params

## What goes wrong
When `params.block_shape` is unset, `override_from_storage` copies the source's block shape. It
also overwrites `params.block_shape_fixed_dims` with the source's flags without checking whether
the caller set them (params.rs:288-303). The caller's flags are dropped without any error. This
contradicts two docs: `override_from_array` says "Fields that are already set in `self` are not
overwritten" (params.rs:254), and `compact_with` says only fields that are not set are inherited
(array.rs:1198). The same params get three different outcomes depending on the path:
- `compact_ndarray_with`, and Python `jix.compact(numpy_array)`, tune first and return
  InvalidArgument "block_shape_fixed_dims is specified but block_shape is not specified"
  (params.rs:351-355; test params.rs:1689).
- `compact_with`, `write_to_with`, and Python `jix.compact(jix_array)` return Ok and drop the
  caller's flags.
- Archive reads keep the file's block shape and deliberately record the caller's flags on it
  (archive/array.rs:546-560; test archive/array.rs:640).

The data stays correct. What is lost is the caller's block layout: the block shape that was
asked for is not used, and the result spec stores flags that later ops propagate.

## Trigger
A source with explicit block shape [8, 32] (all dims fixed), shape (64, 64), i32. Params
`block_shape_fixed_dims = [true, false]`, `block_size = 2048`, `block_shape` unset.
- Expected: either an error (like `compact_ndarray_with`), or the flags honored on the inherited
  shape. Honored means dim 0 stays pinned at 8 and dim 1 rescales to 2048 / 4 / 8 = 64, giving
  block shape [8, 64]. That is what the documented route, explicit `block_shape [8, 32]` plus the
  same flags, produces.
- Actual: Ok, block shape [8, 32], fixed dims all true (the source's). `block_size` is ignored.

The explicit route, `params={"block_shape": [8, 32], "block_shape_fixed_dims": [True, False],
"block_size": 2048}`, stores [8, 64].

## Root cause
`override_from_storage` treats `block_shape` and `block_shape_fixed_dims` as one unit, keyed only
on `self.block_shape.is_none()` (params.rs:288). It then assigns
`self.block_shape_fixed_dims = Some(...)` (params.rs:303) instead of
`get_or_insert`, which every other field uses. By the time `tune` runs (array.rs:1316),
`block_shape` is set, so the "fixed dims without block shape" check (params.rs:351-355) cannot
fire. The ndarray path runs `tune` before any override (array.rs:277), so it does report the
error.

## Suggested fix
Pick one meaning and use it on every path. The option most consistent with the K43 archive-read
fix: in `override_from_storage`, inherit the block shape but keep the caller's
`block_shape_fixed_dims` when they are set. Use `get_or_insert`, and still clear the flags when
the inherited block is over `BLOCK_SIZE_BYTES_MAX`, or let tune reject that case. Then
`compact_with` honors the flags like `read_from` does. The other option is to error in
`compact_with` when the flags are set without `block_shape`. Either way, update the
`block_shape_fixed_dims` docs (params.rs:149-152, jix-py/src/array.rs:1584), which say the
flags "require block_shape".

Not part of this defect: setting only `block_size` on a source with an all-fixed block shape
leaves the inherited shape unchanged. That matches the documented inheritance ("unset fields are
inherited"; `block_size` is "Ignored when all dimensions are fixed").
