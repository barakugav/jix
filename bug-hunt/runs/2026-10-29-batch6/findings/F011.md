# F011: `Dtyped for [T; N]` rejects N == 65535 (off-by-one), although the runtime dtype u8[65535] is valid

- Severity: low  Verdict: confirmed  Category: questionable-semantics
- Location: jix/src/dtype.rs:1210 (related: jix/src/dtype.rs:833-848 `set_shape`, jix/src/dtype.rs:590-593 `new_struct`, jix/src/dtype.rs:283 and 521 and 818 docs, jix-py/src/dtype.rs:105-126 `dtype_from_numpy`)
- Reachability: public Rust API (a compile-time const-eval error, no runtime path)
- Reported by: types-dtyped-derive

## What goes wrong
The `[T; N]` impl asserts `N < Itemsize::MAX as usize`, so `N == 65535` is rejected, while the
assert message ("exceeds ... Itemsize::MAX") and the documented limits ("the total bytes per
element must not exceed `u16::MAX`", dtype.rs:283; "must not exceed `Itemsize::MAX`",
dtype.rs:521/818) all allow 65535. Every runtime constructor (`set_shape`, `new_struct`,
the archive's from_proto, jix-py's `dtype_from_numpy`) accepts a u8 / i8 / bool8 dtype with
inner shape [65535] (itemsize 65535). So an array with that dtype (from numpy or a `.jix` file)
can exist, but it can never be typed in Rust: `<[u8; 65535] as Dtyped>::DTYPE`,
`into_typed::<[u8; 65535]>()`, a derived struct with a `[u8; 65535]` field, etc. are compile
errors. Only 1-byte element types are affected (for larger T, `itemsize *= n` overflows anyway).
No memory-safety or wrong-result impact.

## Trigger
```rust
use jix::dtype::{Dtype, Dtyped, ScalarKind};
let mut d = Dtype::new_scalar(ScalarKind::U8);
d.set_shape(&[65535]).unwrap();               // Ok, itemsize 65535
assert_eq!(d, <[u8; 65535] as Dtyped>::DTYPE); // E0080 at compile time
```

## Root cause
dtype.rs:1209-1212 uses a strict `<` where the limit is inclusive everywhere else
(`set_shape` uses `try_shape_product` + `checked_mul`, which accept a product of exactly
`Itemsize::MAX`). The guard has been there since 592a991.

## Suggested fix
Change the bound to `N <= Itemsize::MAX as usize`. Do NOT drop the guard (the hunter's note that
it is redundant is wrong): for N > 65535, `N as Itemsize` at dtype.rs:1213 truncates (e.g.
N = 65537 -> n = 1, itemsize 1 for a 65537-byte type) before `itemsize *= n` could catch it, which
would make the unsafe `Dtyped` impl unsound. Optionally add a test that `<[u8; 65535]>::DTYPE`
equals the `set_shape(&[65535])` dtype.
