# F029: No bool8 test strategy (Rust or Python) draws a byte other than 0/1, so no property test feeds non-canonical bool8 into any kernel; raw-byte regressions in bitwise, where and sum pass the suite

- Severity: low  Verdict: confirmed  Category: test-coverage
- Location: jix/src/util/test_util.rs:348-356 (related: jix/src/util/test_util.rs:52-56, jix/src/util/test_util.rs:1305-1353, jix-py/python/tests/tests_util.py:55, :85, :162, :167-182, jix/src/scalar/bool.rs:108-128, jix-py/python/tests/test_array_ops.py:756-763, jix/src/ops/bitwise.rs:881)
- Reachability: crate-internal (test infrastructure; no library defect is live today)
- Reported by: util-test-infra

## What goes wrong
Since #89, any non-zero `bool8` byte means true. The PRIMER names kernels that work on the raw
byte as the failure mode to expect. But every bool8 strategy draws only 0x00/0x01:
- `ScalarStrategy for bool8` uses `any::<bool>().prop_map(bool8::from)` (test_util.rs:350).
- `op_safe_non_zero_strategy` is `Just(TRUE)` (:354).
- The default `logical_op_strategy`, `op_safe_strategy`, `comparable_strategy` and
  `maybe_non_finite_strategy` all fall back to `any_strategy` (:52-80).
- `array_strategy_from_shape::<bool8>` inherits the same values.
- The Python mirror uses `st.booleans()` in every bool slot (tests_util.py:55, 85, 162), and
  `carray_strategy` builds the arrays from those values (:167-182).

On 0/1 data, raw-byte `&`, `|`, `^`, a low-bit mask test and a raw-byte sum all give the same
result as the truthiness-correct versions, so the property tests cannot tell them apart.

The only non-canonical coverage is one 4-element test per language (bool.rs:108-128;
test_array_ops.py:756-763). It checks only not / equal / cast-to-u8 / sum. It is far shorter than
the vectorized bodies: the contiguous pipeline uses 8 x (vector bytes / itemsize) lanes, which is
256 lanes for 1-byte items on AVX2 and 512 on AVX-512 (elementwise_pipeline.rs:689-704). It also
never reaches the bulk reduction folds or where's LANES body.

`SimdTestValues` has no bool8 impl (test_util.rs:1340, 1353). The Rust bitwise property tests do
not include bool8 at all (`test_op2!(bitand, ..., [u8, u32])`, bitwise.rs:881).

Correction to the report: no bool8-input op kernel has a hand-written SIMD `*_bulk` body today.
- The bool8 entries of bitwise, cmp, maximum/minimum and not have no bulk fn.
- Casts from bool8 are `bulk="disabled"` (cast.rs:283).
- The only bool8 path marked SIMD is the sum fold (reduction.rs:1548). It canonicalizes each item
  through the scalar `Cast<u64>` before the vector add.

So the missing `SimdTestValues` impl is a hazard for future bool8 bulk kernels. The strategy gap
already hides regressions in today's code paths, as the mutants below show.

## Trigger
Any op on a bool8 array whose bytes include 2, 0x80, 0xFE or 0xFF:
- Rust: `bool8(2)`, a public field.
- Python: `np.array([...], np.uint8).view(bool)` through `jix.asarray` / `jix.compact`.

Such input is never generated by `ScalarStrategy`, `array_strategy_from_shape`,
`carray_strategy` or `carrays2_strategy`.

## Root cause
The bool8 strategies were written when the element type was Rust `bool`, where 0/1 is the whole
domain. #89 made every byte valid but did not widen the strategies (test_util.rs:348-356;
tests_util.py `st.booleans()`). Python elements are Python `bool`s, so a non-canonical byte can
only come from array-level construction. `carray_strategy` builds arrays only from element values.

## Suggested fix
- Rust: `any_strategy` for bool8 should draw `any::<u8>().prop_map(bool8)`, weighted toward 0 and
  including 1, 2, 0x80 and 0xFF. `op_safe_non_zero_strategy` should draw `(1u8..=255).prop_map(bool8)`.
- Rust: add bool8 to the bitwise `test_op2!` lists, and add a bool8 `SimdTestValues` impl with
  edge cases 0, 1, 2, 0x7F, 0x80, 0xFE, 0xFF.
- Python: for np.bool_, draw uint8 arrays and `.view(np.bool_)` them in `carray_strategy` and
  `carrays2_strategy`. Compare against NumPy on `arr != 0`.
- Keep a long (more than 512 + tail elements) non-canonical regression test like step 3 for
  pipeline, reduction and where bodies.
