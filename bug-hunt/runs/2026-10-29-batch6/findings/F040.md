# F040: Arrays read from a .jix file do not carry the file's filters in their spec, so compact() and writes of views over them silently switch to the default byte-shuffle

- Severity: low  Verdict: confirmed  Category: questionable-semantics
- Location: jix/src/archive/array.rs:552 (related: jix/src/storage/params.rs:545, jix/src/storage/params.rs:283-284, jix/src/array.rs:1315, jix/src/array.rs:1337-1342, jix/src/storage/params.rs:63-67, jix/src/array.rs:1171, jix-py/src/array.rs:1544, jix-py/src/archive.rs:167-168)
- Reachability: public Rust API (`Array::read_from_reader` / `read_from_file*` / `read_from_file_mmap`, then `compact()` / `write_to()` of a view) and Python API (`jix.read_array`, then `.compact()` / `jix.write_array(view)`), with default params
- Reported by: concept-untrusted-archives

## What goes wrong
The archive stores the codec and filter list in its BlockTableHeader. On read they go only into
`blocks.decoder_config`, which is used for decoding. The storage spec, which every later
re-encode inherits from, is built from the caller's `ArrayParams`. With the default params its
encoder settings are `EncoderParams::default()` (zstd, level 3, `[ByteShuffle]`), whatever the
file used. So `r.compact()` and `write_to` / `write_array` of any lazy view over `r` (`r + 1`,
`map`, a slice...) re-encode with byte-shuffle. The file's bit-shuffle, or its empty filter list,
is dropped. The same array built in memory keeps its filters in all these cases. Only the
compressed-block copy (`write_to` of `r` itself) keeps the file's filters. This contradicts the
documented contract. ArrayParams (params.rs:63-67) says: "When the copied array is a compressed
array ..., the block shape and codec params are preserved identically by default". `compact()`
(array.rs:1171, jix-py/src/array.rs:1544) and `write_array` (jix-py/src/archive.rs:167-168) say
the same. The block shape, the other half of the params, IS inherited from the file
(archive/array.rs:546-551). The data stays correct; only the encoding changes, and with it the
compression ratio and the encode/decode CPU cost.

## Trigger
Rust: `params.filters(&[Filter::BitShuffle])`. `c = Array::compact_ndarray_with(&x, params)` with
`x` a 64x64 u16 array. Write `c` to a `Cursor`, then `r = Array::read_from_reader(..., ArrayParams::default(), Strict)`.
Then `r.compact()?.write_to(..)` or `r.into_typed::<u16>()?.map(|v| v + 1).write_to(..)`.
Python: `c = jix.compact(np.arange(4096, dtype=np.uint16).reshape(64, 64), params={'filters': ['bit-shuffle']})`.
Write `c` to a BytesIO, then `r = jix.read_array(...)` (BytesIO or `path, mmap=True`). Then
`jix.write_array(r + 1, buf)` or `jix.write_array(r.compact(), buf)`. `filters=[]` gives the same
result: byte-shuffle appears.

## Root cause
`ArrayBlockTableStorageBase::read_from` sets only the block shape (and fixed dims) in the caller's
params, then calls `Self::new(blocks, shape, params)` (archive/array.rs:546-552). `new` builds the
spec with `params.into_spec(...)` (storage/compact.rs:201), which fills a missing encoder config
with `params.encoder_params.unwrap_or_default()` (params.rs:545). The file's
`blocks.decoder_config` (codec + filters, archive/block.rs:409-415) never reaches the spec. Every
re-encode takes its codec from the spec: `override_from_storage` copies `spec.encoder_params()`
(params.rs:283-284), and `compact_into_builder_dyn` builds the Encoder from it
(array.rs:1315, 1337-1342). For in-memory arrays `compact_with` passes the resolved params,
including the encoder settings, to `new` (array.rs:1237-1243), so they survive there.

## Suggested fix
In `read_from` (or in `ArrayBlockTableStorageBase::new` when `params.encoder_params` is `None`),
seed the encoder params from `blocks.decoder_config()`: codec and filters from the file, level at
the default. The archive does not store the compression level, so the "compression level is
inherited" wording should be qualified for file-read arrays. The alternative is to add the level
to the BlockTableHeader.
