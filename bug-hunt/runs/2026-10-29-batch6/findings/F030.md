# F030: Value and shape strategy gaps: float any_strategy is finite-only despite its "full domain" doc, f16 any_strategy is 87% inf/zero (f16 max proptest reduces to +inf 95% of the time), comparable/non-zero sets miss -0.0, inf and real/imaginary-only divisors, blocks are capped at 4 per dim, Python never draws 0-d or non-C layouts

- Severity: low  Verdict: confirmed  Category: test-coverage
- Location: jix/src/util/test_util.rs:42 (doc) and :277 and :313 (f32/f64 `any_strategy`) (related: jix/src/util/test_util.rs:245 (f16 `any_strategy`), :307 and :344 (f32/f64 `comparable_strategy`), :380 (complex `op_safe_non_zero_strategy`), :508-515 (`block_shape_strategy`), :578 and :654 (every array/carray strategy sets that block shape), jix/src/ops/reduction.rs:3786-3793 and :4711-4713 (f16 max / maximum proptests), jix/src/ops/reduction.rs:4708-4710 (a test that relies on any_strategy being NaN-free), jix-py/python/tests/tests_util.py:25 (`shape_strategy`), :40-56 (`any_element_strategy`), :167-182 (`carray_strategy`))
- Reachability: test infrastructure only (crate-internal `pub(crate)` helpers and the Python test helpers; no library code involved)
- Reported by: util-test-infra

## What goes wrong
The shared property-test strategies leave several edge-case regions undrawn, and two docs say
otherwise. (1) `ScalarStrategy::any_strategy` is documented as "full domain" (test_util.rs:42),
but for f32/f64 it is proptest's `any::<f32>()`/`any::<f64>()`. That is
`POSITIVE | NEGATIVE | ZERO | SUBNORMAL | NORMAL` (proptest 1.12.0
`src/arbitrary/primitives.rs:20-27`), so it never draws NaN or +-inf. The Python mirror
`st.floats(width=32)` does draw them. (2) The f16 `any_strategy` maps those f32 draws through
`f16::from_f32`, so 32.2% are +-inf, 55.2% are +-0 and only 12.6% are finite non-zero. The f16
`max` proptest (reduction.rs:3786-3793) therefore checks +inf as the expected 1-D result 95% of
the time, and a finite non-zero max only 1.7% of the time. (3) `comparable_strategy` for floats is
{0, 1, 2.4, NaN}, with no -0.0 and no +-inf. The complex `op_safe_non_zero_strategy` makes both
parts non-zero, so a purely real or purely imaginary divisor is never drawn (the Python mirror
does the same). (4) `block_shape_strategy` caps every block dim at `min(4, s)`, and every
`array_strategy_*`/`carray_strategy_*` sets that explicit block shape. So no property test draws a
block larger than 4 per dim, and none draws the auto (cache-sized) block-shape path. (5) Python's
`shape_strategy` has `min_size=1` in every branch, so it never draws a 0-d shape (Rust's draws
about 0.3%). Python's `carray_strategy` always feeds a packed, aligned C-order numpy array to
`jix.compact`, and nothing mirrors Rust's `layout_strategy` (test_util.rs:721).

I found no library bug that these gaps hide today (see Repro). They are coverage gaps that
could let a future regression through.

## Trigger
- 100,000 deterministic draws of `any::<f32>()` and of `any::<f64>()`: 0 NaN, 0 inf each.
- The same f32 draws mapped through `f16::from_f32`: +-inf 32.2%, +-0 55.2%, finite non-zero 12.6%
  (of which 3.2% are subnormal).
- 20,000 f16 vectors of length 1..=100, the main 1-D branch of `reduction_shape_strategy`
  (reduction.rs:3571): the max is +inf in 95.0% of them, +-0 in 3.1%, and finite non-zero in 1.7%.
- 3,000 draws of Python `tests_util.shape_strategy()`: ndim histogram `[0, 277, 467, 504, 824, 163, 141, 120, 504]`, so no 0-d shape.
- 3,000 draws of Python `tests_util.carray_strategy(np.float32)`: all 2,709 numpy inputs with
  size > 1 are C-contiguous and aligned.
- Literal code: `comparable_strategy` (test_util.rs:307, :344) is `{0.0, 1.0, 2.4, NaN}`. The
  complex `op_safe_non_zero_strategy` (test_util.rs:380) is `(non_zero, non_zero)`.
  `block_shape_strategy` (test_util.rs:514) draws from `1u32..=4u32.min(s.max(1))`.

## Root cause
- test_util.rs:42 promises "full domain", but test_util.rs:277 and :313 delegate to
  proptest's `Arbitrary` for floats. proptest deliberately leaves NaN and infinities out of it.
  This is relied on: reduction.rs:4708-4710 says "`any_strategy` never yields `NaN` for floats,
  so `>` is a total order here". So the defect is the doc plus the missing coverage, not the
  strategy alone. Non-finite values reach the property tests only through
  `maybe_non_finite_strategy`, which only cmp.rs and logical1.rs use. Fixed tests do cover some
  cases (reduction.rs:3820-3837 inf in min, :4004 argmax/argmin NaN, :4461-4494 var/std, cast.rs:694
  NaN cast).
- test_util.rs:245 draws f16 by narrowing a bit-pattern-uniform f32. Only about 40 of the 254 f32
  binary exponents land in f16's finite non-zero range. Above it gives inf, below it gives 0.
- test_util.rs:514 hard-codes 4 as the per-dim block cap, and :578 and :654 always call
  `params.block_shape(..)`. The `block_size` draw does not reach the auto block-shape selection.
- tests_util.py:25-36 uses `min_size=1` in every branch. The Rust zero-length branch is
  `vec(0..=3, 0..=8)`. tests_util.py:167-182 has no counterpart to `layout_strategy`.

## Suggested fix
Fix the doc at test_util.rs:42 ("finite floats: no NaN/inf"). Add a separate full-domain float
strategy (`f32::ANY`) for tests whose reference handles NaN, e.g. cast, `max`/`min` with a
NaN-propagating reference, and codec roundtrip. Draw f16 from its own bits
(`any::<u16>().prop_map(f16::from_bits)`), or narrow an f32 from the f16 range, filtered as needed.
Add -0.0 and +-inf to the float `comparable_strategy`. Let the complex non-zero divisor have one
zero part. In `block_shape_strategy`, sometimes draw up to `s` and sometimes leave
`block_shape` unset. In Python, allow `min_size=0` in the zero-length branch and add a
layout-drawing wrapper (F-order, permuted, step-sliced, offset/unaligned, `broadcast_to`) around
the numpy input to `jix.asarray`.
