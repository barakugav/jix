# F014: An explicit block_shape given to the Plain constructors (plain_ndarray_with / _ref_with / _view_with / plain_ndarray_ptr, Python asarray(params=)) is silently discarded, though the docs say it seeds compact() / write_array()

- Severity: low  Verdict: confirmed  Category: questionable-semantics
- Location: jix/src/storage/plain.rs:135 (related: jix/src/storage/params.rs:357, params.rs:388-405, params.rs:116-123; docs at plain.rs:90-95, 227-231, 320-324, 365-369, 400-405 and jix-py/src/ops/as_array.rs:28-32; Python entry jix-py/src/ops/common/operand.rs:486; same pattern in jix/src/storage/scalar.rs:60)
- Reachability: public Rust API and Python API
- Reported by: storage-compact-params

## What goes wrong
`Plain::new` sets `block_shape_fixed_dims` to all-false whenever the caller left it unset (plain.rs:135-141).
That includes the case where the caller set `block_shape` explicitly. `ArrayParams` documents that
case as all-fixed (params.rs:121-123, 150-152; tune at params.rs:357). With every dim non-fixed, `tune` builds
the scaling seed as all 1s (params.rs:397-405), so the caller's block shape values have no effect.
The Plain's spec holds the auto L1-sized shape instead, and `compact()`, `compact_with()` with
default params, and `write_to()` of the plain array (or of views over it) inherit that shape. The
plain constructors' docs say the params "seed arrays derived from this one (e.g. the block shape
and codec used by Array::compact/compact_with)". The Python `asarray` docstring says arrays "later
created from it (e.g. via compact() or write_array()) ... inherit them". Codec params and
`read_size` are inherited correctly; only `block_shape` is lost. Values are always correct. The
user gets a different block layout than requested. For column blocks requested on a row-major
source, column reads are about 550x slower. Side effect: validation is skipped too, so an invalid
`block_shape` (e.g. `[5000, 0]` on a 16x16 array) is accepted by `asarray` / `plain_ndarray_with`,
while `compact` rejects the same params with "block_shape [5000, 0] is invalid".

## Trigger
Rust: `let mut p = ArrayParams::new(); p.block_shape(&[64, 64]);`
`Array::plain_ndarray_with(Array2::<f32>::zeros((1024, 1024)), p)?.compact()?` -> block shape [12, 1024]
(auto on this host), all dims non-fixed. `compact_ndarray_with(&data, p)` gives [64, 64], all fixed.
The same happens with `plain_ndarray_view_with` and `plain_ndarray_ptr`.
Python: `jix.asarray(src, params={"block_shape": [1024, 1]}).compact()` and `.write_to(...)`, where
`src` is a 1024x1024 float32 C-order ndarray.
Not affected: `Array::compact_nd_ptr` / `compact_ndarray_with` (they run `tune` before building
the Plain, array.rs:314-316, so the fixed dims are already all-true) and `jix.compact(np_arr, params=...)`.

## Root cause
plain.rs:135-141 means "a plain view has no real block boundaries, so its auto block shape should be
freely rescalable". It applies that whenever `block_shape_fixed_dims` is unset, including when
`block_shape` is set. `tune` then fills the fixed dims with all-false
(params.rs:357 sees `Some(all false)`, so the documented "explicit = all-fixed" default never applies).
Non-fixed dims are reset to 1 before `scale_block_shape` (params.rs:397-405), and the validation of
explicit dims (params.rs:389-396) only covers fixed dims. `compact()` then copies the spec's
auto shape and all-false fixed dims through `override_from_storage` (params.rs:288-305).
`Scalar::new` (scalar.rs:60-66) has the same code, but Python only builds 0-d Scalars from user
params, so there it matters only through the `__private` API.

## Suggested fix
In `Plain::new` (and `Scalar::new`), override the fixed dims only when `block_shape` is also unset:
`if params.block_shape.is_none() { params.block_shape(all 1); params.block_shape_fixed_dims = Some(all false); }`.
An explicit `block_shape` then keeps the documented all-fixed default and is validated against the
shape. If keeping it non-fixed is intended, at least validate it and fix the plain / asarray docs.
