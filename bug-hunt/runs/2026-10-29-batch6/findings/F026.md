# F026: A Python bool passed as a dim is silently read as dim 0 / 1 (jix.sum(a, True), a.mean(False), jix.argmax(a, dim=True), concatenate, squeeze, permute_dims), where numpy raises TypeError and jix's own index parser rejects bools since K33

- Severity: low  Verdict: confirmed  Category: questionable-semantics
- Location: jix-py/src/util.rs:289 (related: jix-py/src/util.rs:285 tuple items, jix-py/src/util.rs:198 `normalize_dim`, jix-py/src/ops/reduction.rs:44 multi-dim reductions, jix-py/src/ops/reduction.rs:94 argmax/argmin, jix-py/src/array.rs:1189 and the other `Array` reduction methods, jix-py/src/ops/shape_ops.rs:440/479/521/569/632/872/955/1051/1114/1177/1247 shape-op dims, jix-py/src/ops/shape_ops.rs:276 the K33 `PyBool` guard the dim parsers lack)
- Reachability: Python API
- Reported by: py-ops-reduction-wrappers

## What goes wrong
Every Python dim argument is extracted with pyo3's integer extraction (`ItemOrTuple<i32>`,
`Option<i32>`, `i32`, `Vec<i32>`). pyo3 accepts a Python `bool` there because `bool` subclasses
`int`, so `True` becomes dim 1 and `False` dim 0, `normalize_dim` accepts it, and the op runs over
that dim. A positional flag put where the dim goes - `x.var(True)`, `jix.all(mask, True)` written as
if the second argument were `keepdim` (which is keyword-only) - therefore silently reduces dim 1 or
dim 0 and returns a result of another shape and value instead of raising. numpy's C-level axis
parser rejects a bool axis for every reduction, argmax/argmin, concatenate, squeeze and transpose
(`TypeError: an integer is required`). jix itself is inconsistent: since the K33 fix it rejects a
Python bool as an index (`a[True]` -> TypeError, `test_bool_index_raises`), and it already rejects
the same value spelled `np.True_` as a dim (no `__index__`), so only the Python-bool spelling of a
dim slips through. The K33 write-up (run 2026-10-22-trial2 F020) flagged the dims path and
suggested the same guard; the fix (c009869, "Raise on bool index") touched only
`parse_basic_index`, and no test, docstring or context-doc "Intentional behaviors" entry says bool
dims are accepted.

## Trigger
```python
x = np.arange(6.0).reshape(2, 3); a = jix.asarray(x)
jix.sum(a, True)                    # -> [3., 12.]       (dim 1)   numpy: TypeError
jix.max(a, dim=(True, False))       # -> 5.0             (both)    numpy: TypeError
a.mean(False)                       # -> [1.5, 2.5, 3.5] (dim 0)   numpy: TypeError
jix.argmax(a, dim=True)             # -> [2, 2]          (dim 1)   numpy: TypeError
jix.all(a > 0, True)                # -> [False, True]   (dim 1)   numpy: TypeError
jix.concatenate([a, a], True)       # -> shape (2, 6)              numpy: TypeError
jix.permute_dims(a, (True, False))  # -> shape (3, 2)              numpy: TypeError
jix.sum(a, np.True_)                # TypeError (already rejected)
a[True]                             # TypeError (K33 fix)
```

The script also lists, as information only, `insert_dim`, `stack`, `flip`, `roll` and `swapdims`
with a bool dim: jix accepts all of them, and so does numpy, because those numpy helpers are written
in Python and go through `operator.index` (`np.flip(x, True)`, `np.expand_dims(x, True)`,
`np.swapaxes(x, True, False)` succeed). The numpy comparison therefore supports the claim for the
reductions, argmax/argmin, concatenate, squeeze and permute_dims only. For the other shape ops the
argument rests on jix's own consistency (bool rejected as an index, `np.True_` rejected as a dim).

## Root cause
jix-py/src/util.rs:285 and :289 (`ItemOrTuple::extract`) call `extract::<i32>()` with no bool check,
and the plain `Option<i32>` / `i32` / `Vec<i32>` dim parameters (reduction.rs:94,
shape_ops.rs:632/872/955/1051/1177/1247) use the same pyo3 integer conversion. That conversion
accepts any `int` subclass, `bool` included. `parse_basic_index` got an explicit
`!item.is_instance_of::<PyBool>()` guard for this reason (shape_ops.rs:276), and the dim parsers did
not.

## Suggested fix
Add a dim newtype (for example `PyDim(i32)`) whose `FromPyObject` rejects `PyBool` with TypeError
and then extracts `i32`. Use it as `ItemOrTuple<PyDim>` / `Option<PyDim>` / `Vec<PyDim>` everywhere
a dim is taken, so that every dim argument rejects bools the way indices do. Add a
`test_bool_dim_raises` next to `test_bool_index_raises`. Whether to also reject bools for the
shape ops where numpy accepts them (flip, roll, insert_dim, stack, swapdims) is a judgment call.
One shared parser that rejects them everywhere is the simplest consistent rule.
