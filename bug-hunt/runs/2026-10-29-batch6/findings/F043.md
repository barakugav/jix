# F043: SIMD level coverage: for_each_simd_level! skips the levels the host lacks without saying so, and level-dependent driver code (pipeline lane count, reduction folds, update_bulk fallbacks) runs only at the host's Level::new() level

- Severity: low  Verdict: confirmed  Category: test-coverage
- Location: jix/src/util/test_util.rs:1270 (related: jix/src/util/test_util.rs:1281-1299, jix/src/util/test_util.rs:1305-1350, jix/src/storage/elementwise_pipeline.rs:668, jix/src/storage/elementwise_pipeline.rs:689-704, jix/src/ops/reduction.rs:817, jix/src/ops/reduction.rs:1099, jix/src/ops/reduction.rs:1231, jix/src/ops/reduction.rs:1436-1446, jix/src/ops/reduction.rs:1619-1626, jix/src/codec/filter/bit_shuffle.rs:207-307, .github/workflows/ci.yaml:18)
- Reachability: test infrastructure only. No library defect was found behind the gap.
- Reported by: util-test-infra

## What goes wrong
`for_each_simd_level!` runs `$check` only for the levels that `Level::new()` can prove. It prints
nothing about the levels it skips. Skipping is unavoidable, because a token for a level the CPU
lacks cannot be built. Not saying so is the problem. CI runs on `ubuntu-22.04` runners, often
AMD Zen 3 parts without the Ice-Lake AVX-512 set that fearless_simd 1.1 requires. There every
`*_all_levels` test reports `ok` while its Avx512 arm never ran.

The macro, and the matching loops in byte_shuffle, also drive only kernel bodies (`apply_bulk`,
`cast_bulk`, the shuffle `*_simd` functions). Driver code that branches on the level is only
ever run at the level `Level::new()` picks on the test host:
- the pipeline's lane count (8 x vector bytes / itemsize, elementwise_pipeline.rs:689-704);
- the reduction fold dispatches (reduction.rs:817, 1099, 1231);
- `update_bulk`'s level branches (reduction.rs:1436-1446). Product of i8..u64 into i64/u64 uses
  the scalar loop only on Sse2/Sse4_2 (reduction.rs:1619-1626). Large widening sums use it only
  on Sse2/Neon.

So on an AVX-512 dev box the AVX2/SSE driver branches never run, and on CI the AVX-512 ones never
run. Nothing in the repo forces a lower level: there is no per-level test in those modules and no
CI leg with fearless_simd's `--cfg disable_dispatch_*`.

`SimdTestValues` is also thin. Each op2 body test pairs `values(0)[i]` with `values(5)[i]`, so
only 9 of the 81 int edge pairs and 26 of the 676 float edge pairs are seen. (MIN, -1) and
(inf, inf) never meet. There are no f16, bool8 or complex impls. Only the div/rem test uses
exhaustive special pairs.

Corrections to the hunter's report:
- `map_masks_to_bools`' AVX2 branch (scalar/simd.rs:363) IS covered per level.
  `ops::cmp::tests::simd_bodies_all_levels` calls `apply_bulk` with N = 64, which is a multiple
  of the 32 AVX2 u8 lanes, and `as_avx2()` is `Some` on an AVX-512 host. Only its use at the
  pipeline's production N is tied to the host's level.
- The bit-shuffle `*_simd` functions take `_simd: S` and never use it. They are plain scalar
  loops compiled under each level's target features, so they have no level-dependent logic, and
  their ByteShuffle passes are already tested per level. A per-level test there would guard only
  against codegen differences. The hunter's byte-identical AVX-512 / AVX2 archives already cover
  that.
- Parts of this are already known, though not in KNOWN.md. The PRIMER says the NEON / AVX-512
  paths are unexercised. The batch4 REPORT's "Platform coverage" asks for an Ice Lake+ / aarch64
  run and mid-range SimdTestValues. The batch5 REPORT asks which level CI picks. New here: the
  level-gated driver branches, and that fearless_simd already offers a switch to reach them.

## Trigger
- Run any `*_all_levels` test on a host without the Ice-Lake AVX-512 set (or under valgrind,
  which hides AVX-512). It prints `ok` and its Avx512 arm is skipped without a trace.
- Run any pipeline or reduction test, on any host. Only `Level::new()`'s level is exercised. For
  example, `Product` of an i32 array uses the SIMD `update_bulk` on AVX2/AVX-512 hosts and the
  scalar fallback only on SSE-only CPUs. No test on either kind of host runs both.

Level check: a tiny fearless_simd 1.1.0 program (`scratch/f043_level`) prints `Level::new() =
Avx512` natively on this host and `Level::new() = Avx2` under valgrind 3.22. So the hunter's
native-vs-valgrind comparison really is AVX-512 vs AVX2. I re-checked the hunter's dumps
(`scratch/util_test_infra_dump_{native,vg}.txt`, 5712 lines each). The only differences are 4
i64/u64 `mean` lines, the documented f64 reassociation with i64::MIN/MAX inputs (context
reduction.md, "Reassociation"). The bit/byte-shuffle archives in `scratch/bs_native` and
`scratch/bs_vg` are identical.

A mutant demonstration was blocked. It would mean breaking the Sse-only `update_bulk` fallback in
a scratch crate copy, showing the lib tests still pass at the default level, and showing they fail
with `RUSTFLAGS="--cfg disable_dispatch_avx512 --cfg disable_dispatch_avx2"`. The disk has
about 790 MB free, and one scratch lib-test build takes about 5 GB (`scratch/target-f029`).

## Root cause
The test design assumes that "every level of the CPU" is enough. The macro (test_util.rs:1270-1300)
and byte_shuffle's copies check `level.as_*()` and drop the levels that are missing. Only kernel
bodies are parameterized by a token. Everything above them (pipeline, reduction folds,
`update_bulk`) picks the level internally through `fearless_simd::dispatch!(SimdLevel::new(),
...)`, so a test cannot choose it. CI has a single x86_64 leg with no level override
(ci.yaml:18).

## Suggested fix
- Make `for_each_simd_level!` `eprintln!` the levels it skipped, or fail when an env var such as
  `JIX_REQUIRE_SIMD_LEVELS=avx512` asks for a level the host lacks.
- Add CI legs that run the lib tests (at least ops::reduction, storage::elementwise_pipeline,
  ops::*) with `RUSTFLAGS="--cfg disable_dispatch_avx512"` and with `"--cfg disable_dispatch_avx512
  --cfg disable_dispatch_avx2 --cfg disable_dispatch_sse4_2"`. fearless_simd's `dispatch!` honors
  these (fearless_simd-1.1.0 src/lib.rs:176-180, src/macros.rs:428-435). That covers the
  AVX2 and SSE2 driver branches on any host. For AVX-512, use an Ice Lake+ runner or Intel SDE.
- Widen `SimdTestValues`: several rotations (or the full edge x edge product, in chunks of 64)
  for the op2 bodies, mid-range values (200.0, 40000.0, 3e9), and f16 / bool8 (bytes 2, 0xFF) /
  complex impls.
