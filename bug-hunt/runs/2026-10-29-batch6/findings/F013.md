# F013: Scalar and Plain operands report an L1-sized auto block shape as their granularity, so combine_block_layout lets them override a compact operand's explicit block shape: compact() of `a * 2.0` or `a + ndarray` turns column blocks [1024, 1] into row blocks [1, 1024]

- Severity: low  Verdict: confirmed  Category: questionable-semantics
- Location: jix/src/storage/scalar.rs:60-66 and jix/src/storage/plain.rs:135-141 (related: jix/src/storage/params.rs:387-409 tune scaling, jix/src/storage/params.rs:602-610 field doc, jix/src/storage/params.rs:945-960 combine_block_layout, jix/src/storage/params.rs:281-304 override_from_storage, jix/src/array.rs:1315, jix/src/ops/op2.rs:72, jix-py/src/ops/common/operand.rs:208 and :152, jix-py/src/array.rs:1579-1584)
- Reachability: Python API (every Python scalar, numpy scalar or numpy array operand of an element-wise op, `where`, `clamp`); public Rust API through `Array::plain_ndarray` operands (Scalar is only under `jix::__private`)
- Reported by: storage-compact-params

## What goes wrong
`Scalar::new` and `Plain::new` seed their params with an all-ones block shape and all-false
fixed dims. `into_spec` runs `tune`, which scales every non-fixed dim up to the L1 budget. The
spec therefore reports an L1-sized shape, `[12, 1024]` for f32 1024x1024 on this host, as the
leaf's "minimum read shape that doesn't waste work" (params.rs:602-610). For a scalar or a strided
buffer that granularity is 1 in every dim. `combine_block_layout` takes the per-dim max and unfixes
every dim where the inputs disagree. So `a * scalar` gets block shape `[1024, 1024]` with no fixed
dims, and `compact()` / `write_to()` rescale that from ones with `a`'s 4096-byte block_size. The
result is `[1, 1024]`, the transpose of the user's explicit `[1024, 1]`. The values are correct,
but the layout the user chose is gone. Column reads of the compacted result decode all 1024
blocks: they take 0.029 s instead of 0.000037 s, about 780x slower. The docs say an explicit
block shape "pins the block size for that dimension exactly" through downstream ops
(jix-py/src/array.rs:1579-1584).

The behavior is also inconsistent within jix. The same scalar written as a broadcast 0-d array
(`arr0(2.0).insert_dim(0).insert_dim(0).broadcast(..)`) has spec block shape `[1, 1]`, and
`compact()` keeps `[1024, 1]`. `a + a` keeps it too. An in-tree test states the design goal at
params.rs:1502: "The broadcast must NOT inflate it". Only Scalar and Plain leaves inflate it.
Lazy reads of `a * 2.0` are not measurably slower; the cost appears only once the result is
materialized with compact() or write_to().

## Trigger
Rust:
```rust
let mut p = ArrayParams::new(); p.block_shape(&[1024, 1]);
let a = Array::compact_ndarray_with(&Array2::<f32>::zeros((1024, 1024)), p)?;
(a.view() + Array::plain_ndarray(Array2::<f32>::ones((1024, 1024)))?).compact()?; // [1, 1024]
let s = Array::from_storage(jix::__private::Scalar::new(2.0f32, [1024u64, 1024], ArrayParams::new())?);
(a.view() * s).compact()?;                                                          // [1, 1024]
```
Python: `a = jix.compact(src, params={"block_shape": [1024, 1]})`, then any of
`(a * 2.0).compact()`, `(a + np.ones((1024, 1024), np.float32)).compact()` or
`jix.where(a > 5, a, 0.0).compact()`.

## Root cause
Two choices that are each reasonable on their own combine badly:
- Scalar and Plain mark all dims non-fixed with a ones seed (scalar.rs:60-66, plain.rs:135-141).
  The intent is that compacting such a leaf alone gets the auto shape.
- `into_spec` always runs `tune`, which replaces the ones seed with an L1-sized shape
  (params.rs:387-409). That shape is stored as the leaf's spec `block_shape`.
  `combine_block_layout` (params.rs:945-960) then compares and takes the max of the raw
  `block_shape` values. It ignores whether an input's shape is real storage granularity (fixed) or
  just a scaling seed (non-fixed). The leaf's L1 shape wins the max on every dim where the explicit
  block is smaller, and the disagreement unfixes every dim. `override_from_storage`
  (params.rs:288-304) passes the non-fixed shape and the first operand's block_size on to `tune`.
  `tune` resets the non-fixed dims to 1 and grows the innermost dim first.

## Suggested fix
Make the spec of a non-compact leaf report its real granularity: keep the all-ones block shape for
Scalar and Plain (as Broadcast already does) and auto-scale it only in `compact` / `write_to`,
which rescale non-fixed dims anyway. Optionally, let `combine_block_layout` ignore inputs with no
fixed dims when another input has fixed dims. With only the first change, an explicit `[64, 64]`
still loses its fixed flags (64 vs 1 disagree), so the second change is what really preserves an
arbitrary explicit layout. Add a test: `(a * scalar).compact()` and `(a + plain).compact()` keep an
explicit block shape.
