# F004: 32-bit: Array.__len__ truncates a dim >= 2^32 with `*len as usize`, so len() silently returns shape[0] mod 2^32

- Severity: medium  Verdict: confirmed  Category: wrong-result
- Location: jix-py/src/array.rs:417 (related: jix-py/src/ops/shape_ops.rs:58-98 (broadcast / broadcast_array_impl), jix-py/src/ops/shape_ops.rs:1048 (repeat), jix-py/src/ops/shape_ops.rs:1244 (tile), jix/src/error.rs:186 (check_shape_overflow), jix/src/ops/shape_ops/broadcast.rs:65, pyo3-0.30.1 src/impl_/callback.rs:126-130)
- Reachability: Python API (`len(x)` on 32-bit wheels: x86, armv7, win32)
- Reported by: types-dims-errors, py-core-array-surface-util, concept-untrusted-archives, concept-python-boundary

## What goes wrong
`Array.__len__` returns `Ok(*len as usize)` where `len` is the u64 length of dim 0. On a 32-bit
wheel `usize` is 32 bits, so a dim of 2^32 or more is reduced mod 2^32. pyo3 then converts the
`usize` to `Py_ssize_t` with `try_into`, raising OverflowError only above `isize::MAX`
(callback.rs:126-130), so any truncated value below 2^31 is returned as a valid length. `len(x)`
then silently disagrees with `x.shape[0]` and `x.size` (both u64, lossless). Core accepts such dims
on 32-bit: `check_shape_overflow` bounds only the u64 byte product and each dim at i64::MAX, and a
lazy broadcast / tile / repeat costs no memory. On 64-bit the cast is lossless (dims <= i64::MAX
fit `isize`), so the bug is 32-bit only.

## Trigger
On a 32-bit CPython with the x86 / armv7 / win32 wheel:
`b = jix.broadcast(jix.compact(np.zeros(1, np.uint8)), (2**32 + 5,)); len(b)` returns 5 while
`b.shape[0] == b.size == 4294967301`. `jix.tile(base, 2**32 + 5)` and `jix.repeat(base, 2**32 + 5)`
give the same shape. A dim in [2^32 + 2^31, 2^33) gives OverflowError instead (truncated value
above isize::MAX), so which outcome you get depends on the low 32 bits.

  The same test on the 64-bit host passes: `pointer width 64: ... len() -> Ok(4294967301)`.

  the jix-py extension cannot be built or run for 32-bit in this environment.

## Root cause
jix-py/src/array.rs:417 `Ok(*len as usize)` is a truncating cast of a u64 shape value. Shapes are
u64 everywhere in jix and are never bounded to `usize` on construction (jix/src/error.rs:186 only
bounds the u64 product and each dim at i64::MAX), so the cast is lossy on 32-bit targets. pyo3's
own overflow check (callback.rs:129) runs after the truncation and cannot see it.

## Suggested fix
Convert with a check instead of `as`: `usize::try_from(*len).ok().filter(|&l| l <= isize::MAX as usize)`
(or `isize::try_from(*len)`) and raise `PyOverflowError` when it fails, matching CPython's behavior
for a `__len__` above `sys.maxsize`. Add a 32-bit regression (e.g. the Rust model above, or a
Python test that skips unless `sys.maxsize < 2**32`).
