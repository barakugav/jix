# F011: bitwise_rotate_left/right with a Python int value: an all-Python-int call raises TypeError (the shifts work), and a Python int value next to a typed u32 count is rotated as int8 (-128 for 64, OverflowError for 200)

- Severity: low  Verdict: confirmed  Category: questionable-semantics
- Location: jix-py/src/ops/bitwise.rs:432-443 and :480-491 (the rotate dispatch tables, which pair
  each value type with u32 and list `(i8, u32)` first) (related:
  jix-py/src/ops/common/dispatch.rs:196 and :318-330 (`cast_python_scalars_to_default_precision`
  turns an all-untyped call into `(Int, P8), (Int, P8)`);
  jix-py/src/ops/common/dtype_promote.rs:67-73 (the "untyped int fits unsigned" remap, which no
  longer applies once the count has precision P8); jix-py/python/tests/test_bitwise.py:302-330 and
  test_type_promotion.py:448 (only array/array and `u8_arr` + Python int count are tested))
- Reachability: Python API (`jix.bitwise_rotate_left` / `jix.bitwise_rotate_right`)
- Reported by: py-ops-cmp-bitwise-where

## What goes wrong
The rotate tables are the only bitwise tables whose two slots have unrelated types: the value slot
is `i8..u64`, the count slot is always `u32`. Two input shapes that every other integer op handles
go wrong because of that:

1. Both operands are Python ints. `dispatch_args` defaults all-untyped operands to 64-bit, so the
   count becomes a typed `(Int, P8)`. Int -> UInt is a down-rank, so `Safe` rejects it for the
   `u32` slot in every entry and the call raises
   `TypeError: Op 'bitwise_rotate_left' does not support operands with dtypes [int, int]`.
   `bitwise_left_shift(1, 1)`, `bitwise_and(1, 3)` and `power(2, 3)` all return int64.
2. The value is a Python int and the count is typed (array or numpy scalar). Nothing ties the
   untyped value to a typed operand, so it matches the first entry, `(i8, u32)`, and is rotated
   within 8 bits: `rotate_left(64, u32[1])` silently gives int8 `[-128]`, and
   `rotate_left(200, u32[1])` raises `OverflowError: Python integer 200 out of bounds for i8`.
   The shifts take the dtype from the typed operand (`bitwise_left_shift(64, u32[1])` -> uint32
   `[128]`), and a typed value works (`rotate_left(np.int64(64), 1)` -> int64 128). The width
   picked for an untyped value is an accident of table order, not a rule.

Minor related symptom (same cause, table order): a bool value array is rotated as int8
(`rotate_left(bool_arr, 1)` -> int8), while `bitwise_left_shift(bool_arr, 1)` gives uint8; the
docstring lists only integer value dtypes.

## Trigger
```python
jix.bitwise_rotate_left(1, 1)                                # TypeError [int, int]
jix.bitwise_rotate_right(1, 1)                               # TypeError [int, int]
jix.bitwise_rotate_left(64, np.array([1], np.uint32))        # int8 [-128]
jix.bitwise_rotate_left(200, np.array([1], np.uint32))       # OverflowError ... for i8
jix.bitwise_rotate_left(64, np.uint32(1))                    # int8 -128
```

## Root cause
The generic dispatch assumes an untyped Python int gets its width from a typed partner in the
same table slot type (all other bitwise / arithmetic tables are `(T, T)`), and that
`cast_python_scalars_to_default_precision` (dispatch.rs:318-330) makes all-untyped calls 64-bit.
For rotate, the value slot has no partner (the count's u32 is unrelated), so an untyped value is
resolved by first-match against `(i8, u32)` (bitwise.rs:434, :482); and the default-precision step
turns an untyped count into a typed int64 that can never Safe-cast to u32 (dtype_promote.rs:67-73
only remaps untyped ints), so no entry matches at all.

## Suggested fix
In the rotate wrappers, resolve untyped operands per slot before dispatch: an untyped Python int
value becomes int64 (the default precision used elsewhere), and an untyped Python int count is
cast to u32 with a bounds check (it should stay untyped rather than be defaulted to P8). E.g. a
custom wrapper instead of `define_op2!`, or excluding the count slot from
`cast_python_scalars_to_default_precision`. Optionally reorder the tables to `u8` before `i8` (to
match the shifts for bool) or reject bool values. Add tests for scalar/array combinations.
