# F004: Reshape reads every split/merge reshape (flatten, [N]->[a,b], block-aligned splits) one element at a time, decompressing a whole block per element: 400-5000x slower reads

- Severity: medium  Verdict: confirmed  Category: pathological-performance
- Location: jix/src/ops/shape_ops/reshape.rs:296-314 (related: jix/src/ops/shape_ops/reshape.rs:347-381 per-element read loop, jix/src/ops/shape_ops/reshape.rs:355-367 `flat` decomposition, jix/src/ops/shape_ops/reshape.rs:195-201 and :300 comments that state the intended matching, jix/src/ops/shape_ops/reshape.rs:68-80 constructor scan with the same early exhaustion, jix/src/codec/mod.rs:401-408 `ReadContext` has no block cache, docs at jix/src/ops/shape_ops/reshape.rs:14-23, jix/src/ops/shape_ops/mod.rs:48-53, jix-py/src/ops/shape_ops.rs:708-711, jix-py/src/ops/shape_ops.rs:802-804)
- Reachability: public Rust API (`Array::reshape`, `Reshape::new`) and Python API (`jix.reshape`, `Array.reshape`, `jix.flatten`, `reshape(-1)`)
- Reported by: shape-ops-slice-reshape

## What goes wrong
`Reshape::read_data` pairs each new dim with an orig dim that has the same logical stride.
Matched dims are forwarded as one inner read. Every unmatched dim is iterated one index at a
time. The read-time scan never steps back: when a new dim finds no match, the inner `loop`
advances `orig_dim_idx` past the last orig dim. Every later new dim is then `None`. So when the
leading new dim is a split or a merge, no dim matches at all. The read becomes one 1-element
inner `read_data` per output element. On a Compact inner, each of those reads decompresses a full
block, because `ReadContext` has no block cache. A read then costs N x block_bytes instead of one
pass over the touched blocks.

This is not the documented read amplification. The docs blame shapes "not aligned with the block
layout". The code's own comment (reshape.rs:195-201: "[6,4] -> [2,3,4] ... new dims 1 and 2 are
matched") and line 300 ("last dims always match") describe a scan that matches trailing dims. The
code matches neither. The slowdown happens even when every new row is exactly one stored block.
The values are correct.

## Trigger
- `[N] -> [a, b]` with b > 1, e.g. Compact f32 `[16384]` with `block_shape([1024])`, then
  `.reshape([16, 1024])`. Each new row is exactly one stored block.
- `[a, b] -> [N]` (flatten) with a > 1. Python: `jix.flatten(jix.compact(np.arange(64*64,
  dtype=np.float32).reshape(64, 64))).numpy()`.
- Any reshape whose leading new dim splits or merges orig dims: `[6, 4] -> [2, 3, 4]`,
  `[a*b, c] -> [a, b, c]`.
- Only reshapes whose leading dims are kept unchanged avoid it, e.g. `[N] -> [N, 1]`.

## Root cause
The scan at reshape.rs:296-314 (the constructor's scan at reshape.rs:68-80 does the same):
```rust
loop {
    if *orig_dim_idx >= orig_shape.ndim() { break None; }
    if orig_logical_strides[*orig_dim_idx] == new_logical_strides[new_dim_idx]
        && new_shape[new_dim_idx] >= 1
        && orig_shape[*orig_dim_idx] >= new_shape[new_dim_idx]
    { let matched = *orig_dim_idx as DimIdx; *orig_dim_idx += 1; break Some(matched); }
    *orig_dim_idx += 1;   // a miss consumes orig dims, all the way to the end
}
```
Take `[6, 4] -> [2, 3, 4]` (new strides `[12, 4, 1]`, orig strides `[4, 1]`). New dim 0
(stride 12) misses both orig dims, which exhausts the scan. New dims 1 and 2 then get `None`.
The iteration shape becomes the full request, so reshape.rs:355-380 makes one inner read per
element. For flatten, the trailing dim would also fail the length test (`b >= N`), so a merge
needs range splitting, not only a better scan.

The current per-element `flat` decomposition (reshape.rs:361-366) is correct only because
matched dims are always an equal-length prefix. It leaves matched dims out of `flat`, so a fix
that matches trailing or partial-length dims would give wrong results if `flat` stayed as it is.

## Suggested fix
- Scan: a miss should only skip orig dims whose logical stride is larger than the new dim's
  (logical strides do not increase), so later new dims can still match.
- Matching: let a new dim match an orig dim with the same logical stride when the new length
  divides the orig length, not only when it is equal.
- Read ranges: compute `flat` over all dims. For a matched dim, use
  `(flat / orig_stride) % orig_len + index[d]` as the inner range.
- Merges (flatten): split the requested flat range at orig-row boundaries into head, body and
  tail pieces, with the body as one rectangular inner read.

This gives one inner read per output row, or per orig row, instead of one per element. The
constructor's spec (block_shape 1 on every unmatched dim) should use the same matching.
Alternatively, give `ReadContext` a small last-block cache. That bounds the cost per block but
keeps the per-element call overhead.
