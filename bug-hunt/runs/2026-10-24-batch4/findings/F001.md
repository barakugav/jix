# F001: Array.numpy() returns wrong values (and uninitialized bytes) for arrays whose dtype has an inner shape - numpy's expanded sub-array dims are taken as the array's strides

- Severity: high  Verdict: confirmed  Category: wrong-result
- Location: jix-py/src/array.rs:568-596 (stride loop, `np_arr.strides().iter().rev()` at 570) (related: jix-py/src/array.rs:557 allocation with the sub-array descr, jix-py/src/dtype.rs:76 `dtype_to_numpy` builds `(base, inner_shape)` descr, jix-py/src/util.rs:119-143 `numpy_empty_ordered` transposes with only `ndim` axes, jix-py/src/array.rs:226 `check_output_array` dtype check, jix-py/src/array.rs:605 `data_span`, jix/src/storage/buf.rs:79-87 `from_raw_parts_mut` no-alias contract, callers jix-py/src/array.rs:714 `plain()` and 729 `__getitem__`)
- Reachability: Python API
- Reported by: py-ops-cmp-bitwise-where, elementwise-ops-where-transmute-subdtype

## What goes wrong
For a jix array whose dtype has an inner shape (e.g. `('<f4', (3,))`), `numpy_dtype()` is a NumPy
sub-array descr, and `np.empty` with such a descr EXPANDS it into trailing dims: the allocated
array has `ndim + inner_ndim` dims. `numpy()` then walks `np_arr.strides()` from the end assuming
one NumPy stride per array dim, so the array's outer dims receive the inner sub-array strides
(dim 0 of a `(4,)` array of `('<f4',(3,))` gets stride 4 instead of 12). The read writes each
12-byte element every 4 bytes: elements overwrite each other (violating `StridedBuf::
from_raw_parts_mut`'s no-alias contract) and the tail of the `np.empty` allocation is never written,
so the result contains overlapped values plus uninitialized/stale heap bytes. A permuted
`read_layout_order` raises `ValueError: axes don't match array` instead, and `numpy(out=...)` can
never succeed. The core is correct (Rust `to_ndarray` of the same `SubDtype` and `write_array`
produce the right data); only the Python read-out is wrong. No out-of-bounds write: the misassigned
strides are always <= the real C-order ones, so the span stays inside the allocation.

## Trigger
```python
dt = np.dtype([("id", "<u4"), ("pos", "<f4", (3,))])
a = np.zeros(4, dt); a["pos"] = np.arange(12, dtype=np.float32).reshape(4, 3)
jix.dtype_sub_field(jix.compact(a), "pos").numpy()   # also jix.asarray(a), 2-D struct arrays,
# q[1:4], q.plain(), jix.stack([q, q]).numpy(), jix.read_array(<file of an inner-shape dtype>).numpy()
jix.dtype_sub_field(jix.permute_dims(jix.compact(b2d), [1, 0]), "pos").numpy()  # ValueError
```
Not a trigger: `np.asarray(jix_array)` - `jix.Array` has no `__array__`, so NumPy wraps it in an
object array without calling `numpy()`. Control that works: fully integer-indexed `q[1, 2]` (all dims
dropped, no NumPy stride consumed).

## Root cause
`numpy()` (jix-py/src/array.rs:536-557) allocates with `numpy_empty_ordered(self.numpy_dtype(py)?,
&out_shape, &order)`, where `dtype_to_numpy` (jix-py/src/dtype.rs:75-76) wraps every dtype as
`(base, inner_shape)`. For a non-empty inner shape NumPy turns that into extra trailing dims, so
`np_arr.ndim() == out_shape.len() + inner_ndim`. The stride reconstruction (array.rs:568-596)
assumes `np_arr.ndim() == number of kept dims` and pops strides from the end, consuming the inner
dims' strides first. The same mismatch makes `numpy_empty_ordered` (util.rs:130-143) pass an
`ndim`-long permutation to `PyArray_Transpose` on an `(ndim + inner_ndim)`-dim array, and
`check_output_array` (array.rs:224-230) require an `out` with the sub-array descr, which no real
NumPy array carries (and its shape check compares against the outer shape only).

## Suggested fix
Treat the inner shape as trailing NumPy dims explicitly: allocate with the base descr and shape
`out_shape + inner_shape` (transpose permutation extended with the identity on the inner dims),
then take the array-dim strides from the FIRST `n_kept` NumPy strides (or skip the last
`inner_ndim` before walking in reverse). In `check_output_array`, accept an `out` with the base
dtype and shape `out_shape + inner_shape`, and require the inner dims to be C-contiguous with
stride `base_itemsize` (so each element is a packed `itemsize` block). Add a test with a
sub-array field (1-D, 2-D, sliced, permuted, `out=`).
