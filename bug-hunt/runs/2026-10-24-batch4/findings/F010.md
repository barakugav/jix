# F010: clamp(bool, min, max) returns uint8 while clamp with one bound, maximum and minimum return bool (bool8 is last in the clamp dispatch table, so it is never chosen)

- Severity: low  Verdict: confirmed  Category: questionable-semantics
- Location: jix-py/src/ops/cmp.rs:447 (related: jix-py/src/ops/cmp.rs:436, jix-py/src/ops/cmp.rs:418-419, jix-py/src/ops/cmp.rs:310, jix-py/src/ops/cmp.rs:358, jix-py/src/ops/common/dtype_promote.rs:86)
- Reachability: Python API
- Reported by: py-ops-cmp-bitwise-where

## What goes wrong
`jix.clamp` with both bounds dispatches through its own hand-written table, which lists `u8`
first and `bool8` last. Dispatch takes the first entry that every operand Safe-casts to, and
`Bool -> anything` is always Safe. So an all-bool input always matches `u8` and the `bool8`
entry can never be chosen. The result is `uint8` (values 0/1). With only one bound, `clamp`
forwards to `maximum` / `minimum`, whose tables list `bool8` first, so the result stays
`bool`. The output dtype therefore depends on whether one or two bounds are given. The
docstring lists `bool` as supported and says operands promote "as in jix.maximum()", and
`numpy.clip` keeps bool. The values are correct; only the dtype is wrong.

## Trigger
```python
b = jix.compact(np.array([True, False, True]))
jix.clamp(b, min=False, max=True)                     # uint8 [1 0 1]
jix.clamp(b, min=np.array([False, True, False]),
             max=np.array([True, True, False]))        # uint8 [1 1 0]
jix.clamp(b, min=False)                               # bool (as expected)
jix.minimum(jix.maximum(b, False), True)              # bool (as expected)
```

## Root cause
Dispatch picks the first table entry whose CastKind admits every operand
(jix-py/src/ops/common/dispatch.rs), and `CastKind::Safe` returns true for `(Rank::Bool, _)`
(jix-py/src/ops/common/dtype_promote.rs:86). So for the table at cmp.rs:436-447,
`clamp_op_descriptor::<u8>()` always wins over `clamp_op_descriptor::<bool8>()`. Commit 02ba65d
(#82, "jix.maximum/minimum(bool) -> bool") moved `bool` to the front of the maximum/minimum
tables (cmp.rs:310, 358) but did not change the clamp table, which already existed (#33). No test
catches it because `_clamp_dtypes` in jix-py/python/tests/test_cmp.py:189 leaves out bool.

## Suggested fix
Move `clamp_op_descriptor::<bool8>()` to the front of the clamp table, so the order matches
maximum/minimum. Add `bools` to `_clamp_dtypes` in test_cmp.py, or add a test that checks the
clamp dtype is the same with one bound and with two bounds.
