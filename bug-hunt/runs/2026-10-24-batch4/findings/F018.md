# F018: Dtype::from_fields computes the struct itemsize with an unchecked u16 add before validation, so debug builds panic instead of returning Err on oversized or malformed field lists

- Severity: low  Verdict: confirmed  Category: overflow
- Location: jix/src/dtype.rs:491 (related: jix/src/dtype.rs:663, the checked add in `check_fields`; jix/src/dtype.rs:480, `from_fields`)
- Reachability: public Rust API (`Dtype::from_fields`). Not reachable from Python: jix-py builds struct dtypes only with `Dtype::new_struct`, which takes the itemsize as an argument (jix-py/src/dtype.rs:208). Not reachable from `#[derive(Dtyped)]` either, which uses `new_struct_borrowed_unchecked` (jix-macros/src/lib.rs:225).
- Reported by: elementwise-ops-where-transmute-subdtype

## What goes wrong
`from_fields` derives the itemsize from the last field after sorting by offset, as
`offset + dtype.itemsize()`, using a plain `u16` add. That add runs before `check_fields`, the
function that validates the layout with `checked_add`. If the last field's offset plus its size is
above 65535, a debug build (overflow checks on) panics with "attempt to add with overflow"
instead of returning `Err(InvalidArgument)`. The input does not need to be large. One field at a
bogus offset is enough, and it is invalid anyway because the first field must be at offset 0.
In release the sum wraps, but `check_fields` still rejects the list, either because its own
checked add overflows or because of the offset/itemsize mismatch. So release builds return the
correct `Err`, the wrapped value never reaches a constructed `Dtype`, and there is no memory-safety
impact. This is the one unchecked add left behind by the K42 fix (6f8e220).

## Trigger
```rust
Dtype::from_fields(vec![
    ("a".into(), 0, <[u8; 65000]>::DTYPE),
    ("b".into(), 65000, <[u8; 1000]>::DTYPE),
]);
// or, smaller and invalid regardless of overflow:
Dtype::from_fields(vec![("x".into(), u16::MAX, u16::DTYPE)]);
```

## Root cause
At jix/src/dtype.rs:489-491, `fields.last().map_or(0, |(_name, offset, dtype)| offset + dtype.itemsize())`
assumes the layout has already been validated. Validation happens on the next line, in
`check_fields` (jix/src/dtype.rs:653-676), which does use `checked_add` (line 663).

## Suggested fix
Use `offset.checked_add(dtype.itemsize())` and map `None` to the same
`InvalidArgument "struct dtype itemsize overflow"` error. Alternatively, have `check_fields`
compute and return the end offset (it already does, as `expected_offset`) and use that as the
itemsize in `from_fields` instead of computing it separately.
