# F014: SliceSpec::new / From<&[I]> panic (ArrayVec capacity) on more than 8 items instead of letting Slice::new return InvalidIndex

- Severity: low  Verdict: confirmed  Category: panic
- Location: jix/src/ops/shape_ops/slice.rs:252 (related: jix/src/ops/shape_ops/slice.rs:263, jix/src/ops/shape_ops/slice.rs:68-73 the InvalidIndex check that is never reached, jix/src/util/arrayvec.rs:375 extend_panic)
- Reachability: public Rust API (`jix::ops::SliceSpec::new`, `impl From<&[I]> for SliceSpec`, so also `Slice::new` / `Slice::new_array` / `Array::slice` with a slice argument). Not reachable from Python: `parse_basic_index` (jix-py/src/ops/shape_ops.rs:253) caps the tuple at NDIM_MAX + 1 and emits one item per dim.
- Reported by: shape-ops-slice-reshape

## What goes wrong
`SliceSpec` stores its items in a `DimArray<SliceItem>` (fixed capacity NDIM_MAX = 8), and both
public constructors fill it with `collect()`, which panics with "ArrayVec: capacity exceeded in
extend/from_iter" for 9 or more items. Neither constructor documents a panic, and a `From` impl is
conventionally infallible. The Result-returning `Slice::new` already rejects an item count that
differs from ndim with `InvalidIndex` ("slice has 3 items but array has 2 dims"), but for more than
8 items it is never reached, because the panic fires while building its argument. The input is
always invalid (no array has more than 8 dims), so the only impact is a panic in place of an
`Err`. Same class as K12 (fixed with a documented panic plus a `try_` variant) and K32.
(`Array::slice` documents "Panics if the number of items != self.ndim()", so on that wrapper only
the panic message is off; the defect is in the fallible `Slice::new` path.)

## Trigger
```rust
let a = Array::compact_ndarray(&array![[1i32, 2, 3], [4, 5, 6]])?;
let spec = SliceSpec::new(&vec![SliceItem::new(None, None, 1); 9]); // panics here
Slice::new_array(a, spec) // expected: Err(InvalidIndex)
```
The same happens for `let spec: SliceSpec = ranges.as_slice().into();` with 9 ranges.
Tuple conversions stop at 8 elements, so they cannot hit it.

## Root cause
`SliceSpec { slice: DimArray<SliceItem> }` (slice.rs:245) can hold at most 8 items, but
`SliceSpec::new` (slice.rs:250-254) and `From<&[I]>` (slice.rs:257-265) are infallible and take an
unbounded slice. They `collect()` into the ArrayVec without checking the length, so the overflow
panics inside `ArrayVec::extend_from_iter` before `Slice::new` (slice.rs:68-73) can run its
item-count check.

## Suggested fix
Make the constructors not panic: store a validity marker (e.g. keep the first 8 items plus the
original length, or an `Option`/error flag) and have `Slice::new` report `InvalidIndex` /
`TooManyDimensions` from it; or add a `SliceSpec::try_new` and document the panic on `new` and the
`From` impl, as K12 did for `ArrayParams::block_shape`. At minimum, document the panic.
