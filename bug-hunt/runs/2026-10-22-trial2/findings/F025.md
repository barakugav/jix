# F025: An 8-dim array cannot be indexed with 8 items plus an Ellipsis ("9 were indexed")

- Severity: low  Verdict: confirmed  Category: error-handling
- Location: jix-py/src/ops/shape_ops.rs:250 (related: shape_ops.rs:286-296 the correct post-Ellipsis check; callers shape_ops.rs:201 `jix.slice`, jix-py/src/array.rs:187 `numpy(index)` / `__getitem__`)
- Reachability: Python API
- Reported by: dynamic-python-differential

## What goes wrong
`parse_basic_index` rejects any tuple index with `len > NDIM_MAX` (8) up front, before it
discounts the Ellipsis. On an 8-d array, a full index of 8 ints/slices plus one `...` (valid in
numpy - the Ellipsis just expands to 0 dims) is therefore refused with
`IndexError: too many indices for array: array is 8-dimensional, but 9 were indexed`. The message
is also wrong: only 8 items consume dims. The same index on a 7-d array (7 items + `...`) works,
so the behavior is an off-by-one at the NDIM_MAX boundary rather than a deliberate grammar rule.
No wrong data, no panic - a valid index is spuriously rejected.

## Trigger
```python
e8 = np.arange(256).reshape((2,)*8); j8 = jix.compact(e8)
j8[(0,)*8 + (...,)]                 # numpy -> 0-d
j8[(...,) + (slice(None),)*8]       # numpy -> shape (2,)*8
j8[(1,)*4 + (...,) + (1,)*4]        # numpy -> 0-d
```
Same for `j8.numpy(idx)` and `jix.slice(j8, idx)` (all share `parse_basic_index`).

## Root cause
The early guard at shape_ops.rs:250 exists so that collecting the tuple into a
`DimArray` (stack `ArrayVec` of capacity `NDIM_MAX`) cannot overflow. But a legal index can hold
up to `NDIM_MAX` dim-consuming items plus one Ellipsis, i.e. `NDIM_MAX + 1` raw items. The proper
check (`consumers = raw.len() - ellipsis_count; consumers > ndim`, shape_ops.rs:286-296) already
handles the general case with the right count, but it is never reached for a 9-item tuple. The
early error also reports the raw tuple length instead of the consumer count.

## Suggested fix
Allow `NDIM_MAX + 1` raw items: collect the raw items into an `ArrayVec<_, { NDIM_MAX + 1 }>`
(or count/skip the Ellipsis while collecting) and keep the early guard at `> NDIM_MAX + 1`; leave
the precise "too many indices" error to the post-Ellipsis check at shape_ops.rs:292. Add an
8-d case with `...` to `test_getitem.py`.
