# F027: Array.numpy() docstring promises a C-contiguous result, but the allocation follows read_layout_order (F-order for Fortran asarray / permuted inputs)

- Severity: low  Verdict: confirmed  Category: questionable-semantics (stale API contract)
- Location: jix-py/src/array.rs:491-492 (docstring) (related: jix-py/src/array.rs:531-551 allocation, jix-py/src/util.rs:101-128 `numpy_empty_ordered`)
- Reachability: Python API
- Reported by: dynamic-python-differential

## What goes wrong
The `Returns:` section of `Array.numpy()` says "Without `out`, a brand-new C-contiguous (row-major)
allocation". Since #52 (commit 217ced2, "avoid unnecessary transpose, like numpy `order='K'`") the
fresh array is allocated in the storage's `read_layout_order`, so it is Fortran-ordered (or some other
permutation) whenever the lazy chain bottoms out in a non-C-ordered `Plain` (e.g. `jix.asarray` of a
Fortran array) or a `permute_dims`. Values are always correct. The docstring was written in #44,
before #52, and never updated. A caller that trusts the documented contract and hands the raw
pointer to C (`x.ctypes.data`, `PyArray_DATA` in an extension that skips the flags check, ctypes
interop) reads the elements transposed. Python-level consumers are mostly safe: `tobytes()` defaults
to C order, and `np.frombuffer(memoryview(x))` raises `BufferError` rather than returning transposed
data (the hunter's claim about `frombuffer` does not hold).

## Trigger
```python
f = np.asfortranarray(np.arange(12.0).reshape(3, 4))
jix.asarray(f).numpy().flags                     # C=False F=True strides=(8, 24)
jix.asarray(f)[0:2, :].flags                     # C=False F=True strides=(8, 16)
(jix.asarray(f) + 1).numpy().flags               # C=False F=True
jix.permute_dims(jix.compact(np.arange(12.).reshape(4, 3)), [1, 0]).numpy().flags  # C=False F=True
jix.compact(f).numpy().flags                     # C=True (compact storage reads row-major)
```

## Root cause
`numpy()` (jix-py/src/array.rs:531-551) builds `order` from `spec().read_layout_order()` and calls
`numpy_empty_ordered` (jix-py/src/util.rs:101-128), which allocates C-order in the permuted shape and
`PyArray_Transpose`s it back - a deliberate order='K'-like optimization from #52. The `Returns:`
docstring (array.rs:489-493) still states the pre-#52 contract. No test pins either layout.

## Suggested fix
Most likely doc-only: say the result follows the source's memory order (like NumPy `order='K'`) and
is C-contiguous only for row-major sources; point users who need C order at
`np.ascontiguousarray(a.numpy())` or `a.numpy(out=np.empty(shape, dtype))`. Alternatively add an
`order=` keyword (default 'K') so callers can request C order without an extra copy. Add a test that
pins whichever contract is chosen.
