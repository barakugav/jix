# F026: dtype_from_numpy debug_assert panics on packed numpy struct dtypes whose fields all have alignment 1

- Severity: low  Verdict: confirmed  Category: panic
- Location: jix-py/src/dtype.rs:208-211 (related: jix/src/dtype.rs:611-620, jix/src/dtype.rs:653-688; callers jix-py/src/ops/common/operand.rs:98, jix-py/src/ops/as_array.rs:64, jix-py/src/ops/mod.rs:95)
- Reachability: Python API (debug builds only; release wheels skip the assert)
- Reported by: dynamic-python-differential

## What goes wrong
`dtype_from_numpy` ends with `debug_assert_eq!(dtype.is_aligned() && dtype.fields().is_some(), numpy_dtype.is_aligned_struct())`.
When every field of a struct has alignment 1, the packed and the aligned layouts coincide, and core
`Dtype::new_struct` tries the aligned classification first, so it records `is_aligned = true`.
numpy's `isalignedstruct` only reflects whether `align=True` was passed, so a plain
`np.dtype([('r','u1'),('g','u1'),('b','u1')])` reports `False` and the assert fires. Every numpy
-> jix conversion (`jix.asarray`, `jix.compact`, numpy operands of ops, `dtype=` arguments) raises
`PanicException` in the `maturin develop` debug build used by the Python test suite. Because
`dtype_from_numpy` recurses into fields, a packed all-1-byte sub-struct nested inside an otherwise
ordinary struct (e.g. `[('rgb', [('r','u1'),('g','u1')]), ('w','<i4')]`) also panics. In release
wheels the only effect is cosmetic: numpy dtypes regenerated by `dtype_to_numpy` carry
`align=True` (isalignedstruct True), which numpy treats as equal (`==` True, `can_cast(..., "no")`
True), so results and `out=` are unaffected.

## Trigger
```python
jix.asarray(np.zeros(4, np.dtype([('r', 'u1'), ('g', 'u1'), ('b', 'u1')])))
```
also `[('x','i1')]`, `[('x','?'), ('y','u1')]`, and `[('rgb', [('r','u1'),('g','u1')]), ('w','<i4')]`;
both via `jix.asarray` and `jix.compact`. The `align=True` variants and multi-byte packed structs
(`[('a','i4'),('b','f8')]`) work.

Release-side check (numpy 2.5.4): `np.dtype([('r','u1'),('g','u1'),('b','u1')]) == np.dtype(..., align=True)`
is `True`, both have itemsize 3 / alignment 1, `can_cast` with casting `"no"` is `True` both ways.

## Root cause
The assert assumes jix's `is_aligned` flag and numpy's `isalignedstruct` flag are a bijection.
They are not: core decides `is_aligned` from the layout (`jix/src/dtype.rs:611-613`, aligned check
first, `is_aligned_struct` at :653-688), while numpy's flag records the user's `align=` request. For
alignment-1 structs the layout is both packed and aligned, core picks aligned, numpy says not
aligned. No existing test covers a struct whose fields are all 1-byte (the Rust tests in
`jix-py/src/dtype.rs` and `test_sub_dtype.py` use mixed-width fields).

## Suggested fix
Relax the assert: only require equality when the two layouts are distinguishable, e.g.
`debug_assert!(dtype.fields().is_none() || dtype.alignment().as_usize() == 1 || dtype.is_aligned() == numpy_dtype.is_aligned_struct())`
(or at least `numpy_dtype.is_aligned_struct() => dtype.is_aligned()`). Do not flip core's tie-break
to "packed", which would make the `align=True` numpy variant mismatch instead. Add a Python test
with an all-`u1` struct (and a nested one).
