# F004: K1 fix is incomplete: Decoder::decode runs the filters over a short decompression before the length check, so a failed read writes uninitialized or stale pool bytes into the caller's out buffer

- Severity: high  Verdict: confirmed  Category: memory-safety
- Location: jix/src/codec/mod.rs:315 (related: jix/src/codec/mod.rs:276-279, jix/src/codec/mod.rs:303-312, jix/src/storage/block.rs:192-197, jix/src/storage/compact.rs:324-327, jix/src/storage/compact.rs:464, jix/src/util/buf_pool.rs:40, jix-py/src/array.rs:627)
- Reachability: public Rust API (`Array::read_from_reader` + `to_ndarray_slice` / `to_ndarray_buf(.., Some(out))`), Python API (`jix.read_array` + `Array.numpy(out=...)`)
- Reported by: codec-archive-codec-pipeline

## What goes wrong
The K1 fix (#86) added the check `nbytes == b_size_bytes` to `BlockTable::read_block`
(storage/block.rs:193-197). That check runs only after `Decoder::decode` has returned, and `decode`
has already run every filter over the whole destination, including the bytes zstd never wrote
(codec/mod.rs:315-318). When the filter count is odd, zstd decompresses into a pooled scratch buffer
(codec/mod.rs:276-279). On a fresh pool that buffer is uninitialized heap memory. On a warm
`ReadContext` it holds the bytes of an earlier read, possibly of a different array. The filter reads
that tail, which is UB for uninitialized memory, and writes a permutation of it into `dst`. When the
read is aligned to a single block and the destination is contiguous (compact.rs:324-327), or when it
takes the multi-block direct path (compact.rs:464), `dst` is the caller's own `out` buffer. The read
then returns `Err`, but the caller's initialized buffer now holds uninitialized heap bytes or another
array's data. With an even filter count, zstd writes straight into `dst`, and the first filter reads
`dst`'s never-written tail. For `to_ndarray` that tail is `ndarray::Array::uninit` memory, so this is
another uninitialized read, though the `Err` keeps it from being returned.

## Trigger
1. Write a `u8` array of 64 elements with `block_shape [64]` and `filters [ByteShuffle]`, using `write_to`.
2. Replace the block's zstd frame in place with a frame that decodes to 8 bytes,
   `28 B5 2F FD 20 08 41 00 00 EE x8`, followed by a skippable frame (`50 2A 4D 18` + u32 pad) that
   restores the original length. A frame that decodes to 0 bytes works too. All archive offsets stay
   valid, so `ArchiveValidation::Strict` accepts the file.
3. On a `ReadContext` that has already read another ByteShuffle array `[0x5A; 64]`, call
   `victim.to_ndarray_slice(&[0..64], &mut out /* zeros */, &ctx)`.

Same result with `[BitShuffle]` and with `[ByteShuffle, BitShuffle, ByteShuffle]` on u32. With a
fresh context, `out` receives uninitialized heap memory instead.

Python: `jix.write_array` a 1024-element uint32 array (`block_shape [1024]`). Patch the frame to an
empty frame plus a skippable pad, then call `jix.read_array(...)` and `a.numpy(out=np.zeros(1024, np.uint32))`.

In Python each `Array` caches its own `ReadContext` (jix-py/src/array.rs:165-177). The cross-array
stale-data variant therefore needs a second block of the same array, but the uninitialized-heap
variant reproduces directly. Miri was not used: under `cfg(miri)` the zstd stand-in
`copy_from_slice` (codec/mod.rs:310) panics on any length mismatch, so it cannot produce a short
decode.

## Root cause
`Decoder::decode` (codec/mod.rs:270-320) treats the `nbytes` returned by `decompress_to_buffer`
(codec/mod.rs:305) as information for the caller, never as a precondition for the filter pass. It
runs `filter.decode` over the full `dst.len()` buffers (codec/mod.rs:315-318), which the filters
read in full. Neither the pooled scratch (uninitialized or stale by contract, buf_pool.rs:34-39) nor
the destination is fully written when `nbytes < dst.len()`. The #86 fix moved the length check from
a `debug_assert` to an `ensure!`, but left it in `read_block` (block.rs:193-197), after the side
effects on `dst`. The pilot's F001 suggested the check go in `decode` before the filters run, and
that part was not applied.

## Suggested fix
In `Decoder::decode`, immediately after `decompress_to_buffer`, return `InvalidArchive` /
`CodecError` if `nbytes != decompress_out.len()`, before any filter runs. Keep the `read_block`
check as defense in depth. With that, a one-filter chain leaves `dst` untouched on error. With an
even chain, `dst` holds at most the bytes zstd actually wrote. Optionally reject frames whose header
content size differs from the block size, or frames followed by trailing data.
