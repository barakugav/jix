# F008: Python indexing rejects slice start == dim length, so a[n:], a[n:n] and any slice on a zero-length dim raise IndexError

- Severity: medium  Verdict: confirmed  Category: error-handling
- Location: jix-py/src/ops/shape_ops.rs:342 (related: jix-py/src/array.rs:187, jix-py/src/array.rs:448-449, jix-py/src/ops/shape_ops.rs:201, jix/src/ops/shape_ops/slice.rs:364-371, jix/src/ops/shape_ops/slice.rs:835-838)
- Reachability: Python API
- Reported by: py-ops-shape-ops, dynamic-python-differential

## What goes wrong
`parse_basic_index` checks a slice's normalized start with `start_norm < 0 || start_norm >= len`.
That rejects `start == len`, which is the only possible start of an empty slice at the end of a dim
and the only possible start of any slice on a dim of length 0 (an omitted start resolves to 0).
So `a[3:3]` and `a[3:]` on a length-3 dim fail while `a[2:2]` works, and on an empty array even
`z[:]` fails while `z[...]` and `z.numpy()` work. The parser is shared by `Array.__getitem__`,
`Array.numpy(index)`, `Array.plain(index)` (via `parse_index`, array.rs:187) and `jix.slice`
(shape_ops.rs:201), so all of them raise. This contradicts the `numpy()` docstring
(array.rs:448-449: "An empty slice (`start == stop`) is valid and produces a dim of length 0") and
the core `Slice`, which accepts `start == dim_len` (slice.rs:364-371, pinned by the test
`resolve_accepts_start_equal_to_dim_len_empty_slice`, slice.rs:835-838). Generic code that slices
possibly-empty arrays (empty batches, filtered results, `x[k:]` with k == len) breaks with a
spurious IndexError.

## Trigger
```python
a = jix.compact(np.arange(12, dtype=np.int32).reshape(3, 4))
a[3:3]; a[3:]; a[:, 4:]; a.numpy(slice(3, None)); jix.slice(a, slice(3, None))
z = jix.compact(np.zeros((0, 3), np.int32))   # also jix.asarray(np.zeros((0, 3)))
z[:]; z[0:0]; z[:, 0]; z.numpy((slice(None), 0)); jix.slice(z, slice(None))
```
Expected (docstring, core Slice, numpy): shapes (0, 4), (0, 4), (3, 0), (0, 4), (0, 4), and
(0, 3), (0, 3), (0,), (0,), (0, 3). Actual: IndexError, e.g.
"slice start 3 is out of bounds for dim 0 with size 3",
"slice start 0 is out of bounds for dim 0 with size 0".

## Root cause
jix-py/src/ops/shape_ops.rs:342 applies the integer-index bound (`i < len`, correct for the Int arm
at line 319) to a slice start. A slice start is a fence-post, valid in `[0, len]`; the later
`start_norm > stop_norm` check (line 352) together with `stop_norm <= len` already keeps it in range.
Strict bounds are intentional (py-ops.md "Intentional behaviors"), but no doc or test intends
`start == len` to be out of bounds: the Python test `test_slice_start_out_of_bounds_raises` uses
`slice(10, 12)` on length 3, which a fix keeps rejecting.

## Suggested fix
Change the check to `start_norm < 0 || start_norm > len` (matching core `DimSlice::resolve`'s
`0..=dim_len`), and add Python tests for `a[len:]`, `a[len:len]`, and `z[:]` / `z[:, i]` on a
zero-length dim.
