# Context: operations

For units that touch `jix/src/ops/`. Read `general.md` first.

## Layout of a family file

Ops are grouped by family, with the same file name in both crates
(`jix/src/ops/elementwise/arith.rs` and `jix-py/src/ops/elementwise/arith.rs`). A core family file
holds, in order:

1. `pub(crate) mod traits` - the scalar traits (re-exported as `jix::scalar::*`) and their
   per-dtype impls. The impls are the ground truth for "supported dtypes" and per-element
   semantics. Impls behind `#[cfg(feature = "half")]` / `"num-complex"` cover `f16` / `Complex`.
2. The op structs (`jix::ops::*`), most of them declared through `define_op1!` / `define_op2!`
   with the docs passed as the first macro argument.
3. One `impl Array<S>` block with the methods, many declared through
   `define_array_op1_method!` / `define_array_op2_method!`.
4. `#[cfg(test)] mod tests`.

Reductions (`ops/reduction/`) follow the same idea, with their engine and macros in `common.rs`.
Shape ops (`ops/shape_ops/`) are one file per op and have no scalar trait.

## Docs generated by macros

Some docs are not written at the item but produced by a macro with `#[doc = concat!(...)]`: the
`new` / `new_array` constructors of the op structs, the `Array` methods from
`define_array_op*_method!`, the `*_bulk` trait methods. They look like code to the review gate.
Do not edit them; if one is wrong, put it in your report.

## What the docs of an op should agree on

- The supported dtypes and the output dtype match the trait impls (Rust) or the dispatch table
  (Python).
- Integer behavior: overflow wraps; a result with no integer value (division by zero, negative
  integer power) fails the read with `ErrorKind::Arithmetic` in Rust and raises in Python.
- Float behavior: no errors, `inf` and `NaN` carry them.
- The operator, if any (`-a`, `a + b`, `a & b`), really is implemented for `Array`.
- An op on `Array` takes arrays only. For a constant operand the Rust docs point to `Array::map`.

## Boilerplate that is intended

These sentences repeat across ops so that each item reads on its own. Keep them; only fix one
that is wrong for its op.

- "The result is a lazy view." A doc says that the result is lazy once: this sentence, or "A lazy
  [`jix.Array`] view ..." in a Python `Returns` entry. It does not add "no computation occurs
  until the array is read".
- "See [`jix::scalar::X`] scalar trait for the per-element semantics."
- "This struct is the bare storage implementation, the operation is also available as ..."
