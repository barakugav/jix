# Jix - general context for docs reviewers

This file is a map, not a source of truth. It was written from the code, but where it and the
code disagree, the code wins - and say so in your report.

## What jix is

A multi-dimensional array library written in Rust, with Python bindings. It has two independent
features:

- **Block-compressed storage.** An array is an n-d grid of fixed-size blocks, each compressed on
  its own (filters, then zstd). A read decompresses only the blocks it touches.
- **Lazy operations.** Every operation returns a new array that wraps its input(s). Nothing is
  computed until the result is materialized. In Rust the whole chain is encoded in the static
  type (`Array<Sum<Add<A, B>>>`) and there is no runtime graph. In Python the chain is
  type-erased and each op dispatches on the runtime dtype.

## Packages and where their docs are rendered

| Directory | Package | Docs |
|-----------|---------|------|
| `jix/` | Rust crate `jix` | rustdoc (docs.rs). Crate docs are the `//!` block of `jix/src/lib.rs`. |
| `jix-macros/` | `#[derive(Dtyped)]`, re-exported as `jix::dtype::Dtyped` | rustdoc |
| `jix-py/` | Python package `jix` (PyO3) | mkdocs + mkdocstrings site |
| `jix/schema/` | protobuf codegen; its output `jix/src/archive/schema/_proto_gen/` is generated | out of scope |

There is no Cargo workspace: each crate is built from its own directory.

**Python docstrings live in Rust.** The docstring of a Python function, method or class is the
`///` comment on its `#[pyfunction]` / `#[pymethods]` / `#[pyclass]` item in `jix-py/src/`. The
module docstring is `jix-py/docs/module.md` (pulled in with `include_str!`). `jix-py/python/jix/__init__.py`
only re-exports and defines aliases (`jix.pow`, `jix.abs`, `jix.concat`, ...).

## Core model (Rust)

- `Array<S: ArrayStorage>` is generic over its storage. A storage exposes three things: `shape()`,
  `dtype()`, and `read_data(index, context, out)`, which reads a rectangular region into a
  `StridedBuf`. Everything else is built on these.
- Storages: `Compact<ET>` (heap, block-compressed, the main one), `CompactMmap<ET>` (block-compressed,
  memory-mapped file), `Plain<A, ET>` (uncompressed in-memory buffer), `ArrayStorageAny`
  (type-erased; `ArrayAny = Array<ArrayStorageAny>`), and one op struct per operation in `jix::ops`.
- The element type is tracked twice: at runtime by `Dtype`, and at compile time by the storage's
  `ElementType`, either `Ty<T>` or `TypeDyn`. Element-wise ops need `Ty<T>`
  (`ArrayStorageTyped`); arrays read from a file are `TypeDyn` until `Array::into_typed::<T>()`.
- The number of dims is a runtime property. Shapes are `&[u64]`.
- Materializing: `to_ndarray`, `to_ndarray_sub`, `to_buf_slice`, `to_buf_strided`, `to_plain`,
  `compact`, `compact_with`, `write_to`, `write_to_file`.
- Dtypes: scalars (`i8..i64`, `u8..u64`, `f16`, `f32`, `f64`, `Complex<f32>`, `Complex<f64>`,
  `bool8`), structs (named fields with byte offsets), and an optional inner shape per element.
  `f16` needs the `half` feature and `Complex` the `num-complex` feature.
- Limits: `NDIM_MAX = 8` array dims, `DTYPE_NDIM_MAX = 4` inner dtype dims, little-endian only.
- Errors: integer element-wise ops fail the read with `ErrorKind::Arithmetic` on a result with no
  integer value (division by zero, negative integer power); integer overflow wraps; float ops never
  report errors.

## Where an operation is documented

One operation usually has docs in several places. They must agree on the facts.

| Item | Location | Role |
|------|----------|------|
| scalar trait `jix::scalar::X` | `pub(crate) mod traits` at the top of the family file in `jix/src/ops/` | per-element semantics, supported dtypes |
| op struct `jix::ops::X` | same file, `define_op1!` / `define_op2!` or a plain struct | the lazy view; usually holds the Rust example |
| `Array::x` method | same file, `impl Array<S>` | often a one-line doc generated by a macro |
| Python function `jix.x` | same file name under `jix-py/src/ops/` | full Python docs: dtypes, promotion, Args, Returns, Examples |
| Python `Array.x` / operator | `jix-py/src/array.rs` | usually a one-line pointer to `jix.x` |

Names differ between the languages (`neg` / `negative`, `bitand` / `bitwise_and`, `ln` / `log`,
`select` / `where`, `is_nan` / `isnan`, ...). Check a name against `api_index.md`, never against
memory.

## Vocabulary

The terms the docs use. Another word is a finding only where it names the same jix concept.

- **dim, dims** - not axis / axes, except when naming a NumPy or ndarray API or concept
  (`numpy.swapaxes`, "a reversed axis" of an ndarray).
- **block** - a cell of the storage grid. "chunk" is used for other things (a piece of a read, a
  piece of a dataset) and is wrong only where it means a storage block.
- **compact** - block-compressed storage. **plain** - uncompressed storage (not "non-compressed"
  or "not-compressed").
- **lazy view** - the result of an operation. **materialize** - produce its data.
- **element-wise** in prose (not "elementwise").
- **inner shape** - the fixed shape of one element of a dtype.
- `bool8` is the Rust boolean element type; `bool` is right in Python docs.

## Renames (stale names to watch for)

From the git history. A doc still using a name on the left is stale. Confirm with `api_index.md`.

| Old | New | Where |
|-----|-----|-------|
| `axis`, `keepdims`, `astype` | `dim`, `keepdim`, `cast` | both |
| `bool` element type | `jix::scalar::bool8` | Rust |
| `to_ndarray_buf`, `to_ndarray_slice` | `to_buf_strided`, `to_buf_slice` | Rust |
| `where_condition` | `select` (Rust), `where` (Python) | both |
| `divide_floor` / `divide_trunc` / `divide_euclid`, `remainder_*` | `divide(..., rounding_mode=)`, `remainder(...)` | Python only; the Rust methods still exist |
| `is_nan`, `is_finite`, `is_infinite` | `isnan`, `isfinite`, `isinf` | Python only; the Rust methods still exist |
| `errstate` | removed; integer errors always raise, floats never | Python |
| `D: Dimension` generic on storages and ops | removed; ndim is a runtime property | Rust |
| `storage::View<S>`, `Array<View<S>>` | removed; `Array::view()` returns `Array<&S>`, and `&S` is itself a storage | Rust |

Files under `jix/src/ops/` and `jix/src/` were also moved around recently, so a doc that names a
source file or module path may be stale.

## Repo rules that apply to docs

- **ASCII only.** Use `-`, not an em dash; no unicode arrows, quotes or math symbols.
- Rust lines are at most 100 columns (rustfmt); wrap doc comments accordingly.
- `cargo doc` runs with `-D warnings`: an intra-doc link must resolve.
- Rust doc examples are compiled and run by `cargo test --doc`. Python examples are fenced
  `python` blocks, and the self-contained ones (with `import jix`) are executed by
  `scripts/docs_review/run_py_examples.py`.
